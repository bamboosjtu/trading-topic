# bank-dca 研究回测 vs 桌面应用回测：代码实现差异

> 比较对象：
> - Research 域：`research/bank-dca/src/bank_dca_research/analysis.py`（含 `verify_returns.py`、`build_report.py` 调用方式）
> - Src 域：`src/desktop/electron/domain/analysis.ts`（`simulateBacktest`）+ `src/desktop/electron/domain/finance.ts`（`xirr` / `drawdownProfile`）
>
> 输出日期：2026-07-28
>
> 比较方式：只读对照，未修改任何代码
>
> 适用原则（来自 `AGENTS.md` L9-13、L53 与 `docs/decisions/0001`）：三域隔离是设计目标，相似的回测算法是**有意重复**，不构成"应抽取共享核心"的代码异味。因此本文档的目的不是"找出该统一的差异"，而是**逐维度列出真实差异、说明各自取舍、并标注哪些差异属于有意隔离（应保留）、哪些属于可对齐但当前未对齐（仅记录，不建议跨域改动）**。

## 0. 一句话总览

两者都做"按月定投、分红再投资、XIRR 估值、最大回撤基于 nav"这件事，但**抽象层级不同**：

- **Research 是净值驱动**：先把标的价格 + 公司行动压缩成一条总回报净值序列（`build_stock_level` / `build_index_level` / `build_repo_level`），再对净值序列做按月买入（`simulate_level_dca`）。回测和估值在同一序列上闭环，结构最简、最适合做"分红 vs 不分红""官方全收益 vs 价格指数""滚动 N 年"等对比性研究。
- **桌面是事件驱动**：在逐交易日推进的真实价格序列上模拟账户，外部投入、分红到账、送股转增、再投资都产生独立流水（`contribution` / `buy` / `dividend` / `dividend_reinvest` / `share_adjustment`）。结果包含可审计的逐笔记录、期末持仓、期末现金，更贴近"用户实际账户行为"。

差异是各自域定位的产物，不是实现优劣。

## 2. XIRR 算法差异

| 维度 | Research `calc_xirr` (analysis.py L12-35) | 桌面 `xirr` (finance.ts L12-57) |
| --- | --- | --- |
| 求根方法 | **牛顿法**（带一阶导数） | **二分法** |
| 年基（日/年） | `365.25 * 86400` 秒 | `365.25`（`daysBetween` 用 86_400_000 ms / 365.25） |
| 初始猜测 | `guess = 0.05` | 不需要 |
| 迭代上限 | 200 次 | 区间扩展 24 次 + 收敛 120 次 |
| 收敛阈值 | 步长 `1e-10`，残差 `1e-6` | NPV 绝对值 `1e-7` |
| 下界保护 | `max(guess - npv/derivative, -0.99)` | 初始 `low = -0.9999`，区间不扩展到负无穷 |
| 上界扩展 | 无（牛顿步直接更新） | `high *= 2` 直到 `lowValue * highValue ≤ 0` 或 24 次后失败 |
| 输入符号约束 | `np.all(>= 0)` 或 `np.all(<= 0)` 时返回 NaN | 必须同时存在正负现金流，否则返回 null |
| 退化处理 | 导数绝对值 < `1e-12` 时 break 并按残差判断 | 区间仍同号时返回 null |

**实际影响**：在"持续投入 + 期末赎回"典型现金流上，牛顿法收敛更快、需要的迭代步更少；二分法更稳健但收敛较慢。两域典型的银行股定投样本（约 80 个月投入 + 1 笔期末赎回），数值结果在显示精度（小数点后 2 位）内一致，但**未做跨域数值回归**——研究域没有把任何 XIRR 数值作为预期结果传给桌面测试。

**判断**：属于有意隔离。算法路径、迭代上限、收敛阈值都是实现细节，统一反而会引入隐式耦合。**不建议对齐**。如果未来要做跨域一致性验证，正确做法是按 AGENTS.md L52 用复制向量在桌面域断言预期数值，而不是让两边算法变成同一段代码。

## 3. 净值构建 vs 事件推进：核心架构差异

这是两域**最根本**的差异，其它差异几乎都从这里派生。

### 3.1 Research：两阶段、净值驱动

阶段 1：把原始价格 + 公司行动压缩成一条**总回报净值序列** `level`（`build_stock_level` L38-69）：

```python
# 简化伪代码
for position in range(1, len(frame)):
    gross_return = (
        closes[position] * (1.0 + bonus[position]) + cash[position]
    ) / closes[position - 1]
    levels[position] = levels[position - 1] * gross_return
```

阶段 2：对净值序列做按月买入（`simulate_level_dca` L102-178），每股投入转换为"净值单位数"：

```python
daily["units_bought"] = daily["external_flow"] / daily["level"]
daily["total_units"] = daily["units_bought"].cumsum()
daily["portfolio_value"] = daily["total_units"] * daily["level"]
```

**特征**：
- 价格和公司行动在阶段 1 已经被"消化"进净值，阶段 2 完全不感知单笔分红、送股事件。
- 没有持仓股数、没有现金账户、没有交易流水。
- 分红再投资是隐式的：通过 `reinvest_dividends=True/False` 在阶段 1 切换是否把 `cash` 计入 gross_return。
- 投资单位是"净值单位"（如工商银行净值在 2020-01-02 = 4.53，3000 元买入 662.25 单位），不是真实股数。

### 3.2 桌面：单阶段、事件推进

逐交易日循环（`simulateBacktest` L214-342），每日按顺序处理：

1. **送股/转增**：按登记日收盘后的历史持仓计算应得股数（`holdingsHistory.filter(date <= recordDate).at(-1).shares`），用 `shareIncreaseRatio = (transfer + bonus) / 10` 比例增加持股，产出 `share_adjustment` 流水。
2. **现金分红**：按登记日持仓 × 每股派息计算金额，进 `dividendCash` 池；立即用全部分红池买入原标的（`dividend_reinvest` 流水），允许零碎股。
3. **定投买入**：按 `scheduled` 表，每月计划日投入 `monthlyAmount` 进 `dcaCash`，立即全额买入（`buy` 流水）。
4. **nav 计算**：独立于上面三类事件，按除权日分红累乘得到"标的总收益净值"，仅用于回撤口径。

**特征**：
- 持仓股数、现金、累计投入、累计分红都是显式状态变量。
- 每笔事件都有独立流水，可审计、可导出 XLSX。
- 分红再投资是显式的：分红先进 `dividendCash`，再触发 `dividend_reinvest`。
- 投资单位是真实股数，且 `roundShares` 内部保留 6 位小数、`roundMoney` 在边界保留 2 位。

### 3.3 派生差异

| 派生差异 | Research | 桌面 | 是否有意 |
| --- | --- | --- | --- |
| 分红到账日 | 隐式：在 `build_stock_level` 阶段按除权日计入 gross_return | 显式：默认 `ex_date`，可选 `payment_date`（到账日不是交易日则顺延到下一个有收盘价的交易日） | 有意。研究为口径对比服务，桌面贴近真实账户行为 |
| 送股/转增 | 隐式：通过 `bonus_share_ratio` 在 gross_return 中放大分子 | 显式：`share_adjustment` 流水 + `holdingsHistory` 登记日股数 | 有意 |
| 现金留存 | 不可能：分红再投资是布尔开关，无中间状态 | 默认不留存（再投资为 0 费用、零碎股全额买入），但架构上允许 `dividendCash` 滞留 | 有意。研究是理想化"满仓"，桌面贴近实际 |
| 期末估值 | `final_value = total_units × level[-1]`，即"全部赎回" | `endingAsset = shares × lastClose + totalCash`，同样视为全部市值变现 | 一致，无差异 |
| 月内买入日选择 | 每月第一个交易日（`groupby(period).head(1)`） | 用户指定 `buyDay`（1-28），跨月顺延到下一个交易日，上月顺延不占用本月 | 有意。研究固定口径便于跨标的横向对比；桌面贴近用户实际习惯 |

## 4. 净值构建公式对照（最关键的等价点）

虽然两域架构不同，但**标的总收益净值的构建公式在数学上等价**：

| 公式 | Research (`build_stock_level` L64-67) | 桌面 (`simulateBacktest` L320-327) |
| --- | --- | --- |
| 日 gross return | `closes[t] × (1 + bonus[t]) + cash[t]) / closes[t-1]` | `close × (1 + shareRatio) + dividendPerShare) / prevClose` |
| 累乘 | `levels[t] = levels[t-1] × gross_return` | `nav = nav × gross_return` |
| 起点 | `levels[0] = closes[0]` | `nav = 1`（首日初始化） |
| 起点归一 | 否（保留原始价格起点） | 是（归一到 1） |

差异只在归一基准：Research 的 `level` 起点是原始收盘价（如 4.53），桌面 `nav` 起点是 1。这影响"投入金额转单位数"的绝对数值，但不影响收益曲线形状、XIRR、回撤。

**注意**：`bonus_share_ratio`（Research，已除以 10 转成每股比例）和 `shareRatio = transferRatio + bonusRatio`（桌面，仍是每 10 股比例，乘时用 `shareIncreaseRatio = ratio / 10`）的口径不同——Research 在数据获取阶段 `data_fetch.py` L119-122 就除以 10 落盘；桌面在数据适配器层保留每 10 股比例，回测时再用 `shareIncreaseRatio` 除以 10。**最终代入公式时口径一致**，差异只在中间表示。

## 5. 回撤口径对照

| 维度 | Research | 桌面 |
| --- | --- | --- |
| 最大回撤基于 | 三种净值：`asset_nav`（标的净值）、`strategy_nav`（剔除外部投入的策略净值）、`pnl_on_principal`（账户相对本金） | 单一 `nav`（标的总收益净值），通过 `drawdownProfile` 计算 |
| 摘要字段 | `asset_max_drawdown_pct` / `strategy_max_drawdown_pct` / `max_principal_loss_pct` 三列并排 | `maxDrawdown` / `maxDrawdownPeakDate` / `maxDrawdownTroughDate` / `longestDrawdownMonths` / `longestDrawdownStart` / `longestDrawdownEnd` / `longestDrawdownRecovered` |
| 是否给出回撤区间日期 | 否，只有百分比 | 是，含峰值日、谷值日、最长持续月数、是否恢复 |
| 一致性自检 | `verify_returns.py` L38-42：要求 `asset_nav` 与 `strategy_nav` 最大误差 ≤ 1e-10，否则抛 AssertionError | 无显式自检；通过单测（`analysis.test.ts` P0-2 用例）锁定口径 |

**判断**：桌面更详细（带日期、带最长回撤周期），是产品 UX 需要；Research 更精炼（三种净值并排便于学术对比）。差异有意。但有一个**等价性结论**值得记录：

> 在"满仓、零碎股、分红立即再投资、零费用"模型下，Research 的 `asset_nav` 与 `strategy_nav` 应严格相等（误差 ≤ 1e-10）；桌面 `nav` 即标的总收益净值，等价于 Research 的 `asset_nav`。因此**同一标的同时长、同一起止月、同分红处理口径下，桌面的 `maxDrawdown` ≈ Research 的 `asset_max_drawdown_pct`**，差异来自买入日选择（每月第一个交易日 vs 用户指定日）和净值起点归一。

## 9. 差异清单（按"是否可对齐"分类）

### 9.1 有意隔离，不应统一（AGENTS.md L9-13 / L53 / 决策 0001 L31-33）

- 三份独立的 XIRR 算法（牛顿法 vs 二分法）
- 净值驱动 vs 事件推进的回测架构
- 三份独立的数据适配器（requests / fetch）
- 三份独立的最大回撤实现
- 不同的买入日选择策略（每月第一个交易日 vs 用户指定日）
- 不同的基准范围（多基准对比 vs 单标的服务）
- 不同的测试用例焦点（口径正确性 vs 账户行为正确性）

### 9.2 可对齐但当前未对齐（仅记录，不建议跨域改动）

- **数据来源元信息字段**：桌面 `DataProvenance` 含 `caliberVersion`，Research `manifest.json` 没有 `source_commit`（见 `review.md` P1-2）。两域可独立各自补齐字段，不需要互相 import。
- **回撤摘要字段**：桌面含 `maxDrawdownPeakDate` / `longestDrawdownMonths` 等，Research 只有百分比。两域各自按需求扩展，不需要对齐。
- **月份 vs 日期输入**：Research 用月份字符串、桌面用日期字符串。这是各自抽象层级决定的，对齐会破坏各自的最简表达。
- **月度金额**：Research 是模块常量 3000，桌面是请求参数。研究域是固定样本研究，桌面是用户配置工具，对齐无意义。

### 9.3 数学等价点（重要，但不应据此统一实现）

- **标的总收益净值构建公式**：两域在数学上等价（见第 4 节）。这是设计上的"行为契约等价"，不是"实现应当合并"。如果未来要做跨域一致性验证，正确做法是按 `tests/fixtures/README.md` L1-3 的规范，在桌面域落地一个带预期值的复制向量实例，而不是把 `build_stock_level` 与 `simulateBacktest` 的 nav 计算合并。

## 10. 小结

| 维度 | Research | 桌面 | 关系 |
| --- | --- | --- | --- |
| 抽象层级 | 净值驱动 | 事件推进 | 互补，非冗余 |
| XIRR 算法 | 牛顿法 | 二分法 | 有意隔离 |
| 回撤口径 | 三种净值并排 | 单一 nav + 详细日期 | 有意隔离 |
| 数据来源 | 多基准（行情+分红+指数+回购） | 单标的（行情+分红） | 有意隔离 |
| 测试焦点 | 口径正确性 | 账户行为正确性 | 有意互补 |
| 数学等价点 | 标的总收益净值公式 | 同公式 | 行为契约等价，不应统一实现 |

两域在"按月定投 + 分红再投资 + XIRR + nav 回撤"这一核心金融口径上**意图一致、公式等价**，在**实现路径、抽象层级、辅助字段、数据来源**上**有意分叉**。分叉符合 AGENTS.md 与决策 0001 的隔离原则，本文档不做任何"建议统一"的推荐。
