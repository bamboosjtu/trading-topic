# 攒股收息 R1 产品域复核

> 范围：`src/desktop/` 与 `docs/product/`
>
> 复核日期：2026-07-28
>
> 当前定位：股票与 ETF 证券投资研究，不承担券商账户记账

## 结论

本轮评审意见属实，原实现把证券投资收益和券商账户余额混为一体，且行情只有
单一来源。实现现已收敛为买入、卖出、现金分红和审计调整四类事实，并以投资
现金流统一重建当前持仓、已清仓历史、收益日历和 XIRR。

## 已复核并修复

| 项目 | 当前实现 |
| --- | --- |
| 事实类型 | 普通入口仅买入、卖出、现金分红；修正和冲正只能从原记录发起 |
| 收益核心 | 买入及费用为负现金流，卖出净收入和分红为正现金流，期末持仓市值为期末正现金流 |
| 持仓指标 | 持仓市值、买入支出、卖出净收入、净投入、未实现/已实现收益、分红、总收益、收益率、XIRR |
| 已清仓标的 | 不进入当前持仓表，但继续进入累计收益和 XIRR |
| 修正语义 | 最新有效事实按自己的业务日期历史重述；录入与修正时间只用于审计 |
| 组合录入 | “分红并再投入”在一个 SQLite 事务中写入两条共享关联编号的事实 |
| 日度归因 | 总收益 = 市场价格收益 + 分红收益 + 交易影响 |
| 行情截止 | 统一按 A 股最近已完成交易日；盘中不确认当日正式收盘 |
| 行情供应商 | 腾讯主源；失败时新浪重取完整区间；不拼接；重叠数据明显冲突时阻断 |
| 来源追踪 | 保存并导出实际来源、主源、切换原因、获取时间、截止日和复权方式 |
| 数据质量 | 当前月份支持 stale；已结束历史月份只按所需区间完整性判断 |
| 名称与类型 | 完整证券目录优先，其次最新有效用户事实，再推断，最后回退代码 |
| 持久化 | Schema 8 直接重建，不保留旧模型或旧备份兼容层 |

## 唯一领域路径

```text
ledgerCommands.ts
        ↓
ledgerReducer.ts
        ├─ ledgerQuery.ts
        ├─ positionsView.ts
        └─ dailyAttribution.ts → incomeCalendar.ts
```

`ledgerReducer.ts` 是投资事实有效版本、稳定顺序、持仓数量、剩余成本和累计现金流
的唯一归约入口。Renderer 只展示领域结果，不重算收益。

行情路径为：

```text
MarketDataProvider
├─ TencentProvider（主源）
└─ SinaProvider（完整区间备用源）
        ↓
统一格式与金融校验
        ↓
market_prices / live_market_prices
```

回测证据缓存与实际投资估值缓存继续物理隔离，不因运行过回测而偶然补全实际
投资收益。

## 验证关注点

- 没有额外账户事实也能计算投资收益；
- 分红再投入只确认一次分红收益；
- 已清仓现金流可以闭合 XIRR；
- 业务日期早于修正操作日时，历史月份与当前累计使用同一有效版本；
- 当日没有正式收盘价时进入 partial；
- 腾讯和新浪的明显价格冲突必须返回错误；
- JSON 备份拒绝旧 Schema 与非法事实/行情来源；
- 代码、IPC、XLSX、UI Brief、PRD 与架构使用同一契约。

最终命令结果以本次交付说明为准，不在评审文件中写死测试数量和构建体积。
