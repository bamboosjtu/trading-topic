# 桌面应用数据源

> 梳理日期：2026-08-08
> 审计起点提交：`943dac8e4c706e6dac3dbb2306852854cf01f525`
> 适用范围：`src/desktop/` 产品域；不描述 Labs 或 Research 的运行时
> 市场与币种：沪深京 A 股、境内交易所 ETF，人民币（CNY）

## 结论

桌面应用不安装、不 import、也不执行 Python 或 AKShare。它在产品域内用Node.js/TypeScript 独立实现数据适配器；产品测试只使用产品域 fixture 和 mock。

但“不依赖 AKShare”不等于“上游稳定”。当前应用仍直接访问腾讯、新浪、东方财富和百度股市通的网页后端接口。这些接口没有面向本应用的版本契约或可用性 SLA，页面改版、限流、风控、字段变化和历史覆盖变化都会影响产品。停复牌主源与备用源分别位于东方财富和百度域名，避免共享同一风控面；公司行动仍是东方财富单点。

当前路由的核心原则是：

1. 证券主目录尽量使用交易所官方列表；
2. 行情使用腾讯主源、新浪整段备用，并对两个候选执行相同校验；
3. 自动降级只发生在业务语义一致的日线之间，不跨复权口径拼接；
4. 双源都空不代表休市，必须由独立官方交易日历确认；
5. ETF 目录固定使用新浪整表接口，不再先请求东方财富；
6. 停复牌使用东方财富新市场级报表主源、百度股市通独立备用源，只有完整分页和日期覆盖通过后才替换证据；
7. 公司行动暂时依赖东方财富单源，失败时不得伪装成“无事件”；
8. 所有可消费结果都保存实际来源、约定主源、是否兜底、切换原因、获取时间、数据截止日、复权口径和计算口径版本。

## 业务数据源总表

| 业务数据 | 产品用途 | 主源 | 备用或独立证据 | 口径 | 失败策略 |
| --- | --- | --- | --- | --- | --- |
| 沪深京全 A 股目录 | 标的检索、资产类型与上市日证据 | 上交所、深交所、北交所公开列表组成的复合主源 | 上次成功的本地完整快照；没有门户自动替代 | 股票代码、简称；沪深尽量保留上市日 | 三地必须同时成功且合并后不少于 1,000 只，才覆盖快照；否则回退旧完整快照或报错 |
| 境内交易所 ETF 目录 | 实盘录入标的检索 | 新浪基金行情中心 | 上次成功的本地完整快照；没有自动门户备用 | 代码、简称、`securityType=etf` | 新浪整表必须不少于 1,000 只才覆盖快照；请求或完整性失败时只用旧完整快照或报错 |

| 前复权 OHLCV | 回测页 K 线浏览 | 腾讯 `newfqkline` qfq | 新浪前复权短日线，或全量 KLC + 独立前复权因子 | 真实日 OHLCV、前复权；周/月由日线聚合 | 与计算行情分开获取；失败不伪造 OHLC，只把图表标为 unavailable/error 并记录告警 |

| 已实施配股 | 回测报告“不参与配股”事件 | 东方财富 `RPT_IPO_ALLOTMENT` | 无自动备用 | 登记日、除权日、每 10 股配股比例、认购价 | 同公司行动；不能因源不可用而把事件静默删掉 |
| 证券停复牌区间 | 解释交易所开市但个股无行情的缺口 | 东方财富 `RPT_CUSTOM_SUSPEND_DATA_INTERFACE` | 百度股市通 `notify_suspend` 独立备用；用户公告人工补证 | 明确截止日直接使用；复牌日换算为前一日；东财当前开放记录只保存到本次已观察截止日 | 按回测或持仓范围批量请求；主源全分页失败后整段切换百度分段分页；仅在已确认覆盖范围内原子替换，失败保留旧自动证据和全部人工证据 |
| 交易日历 | 证明法定休市、确定正式估值截止与行情尾部 | 应用内置年度 JSON，来源为上交所年度休市安排 | 无供应商行情替代 | 年度状态为 `official` 或 `pending_official_schedule` | 双源空响应只有在日历确认整个区间休市时才能持久化为空覆盖；当前年度非 official 时发布构建失败 |

交易所公开入口可从[上交所股票列表](https://www.sse.com.cn/assortment/stock/)、[深交所股票列表](https://www.szse.cn/market/stock/company/)、[北交所股票列表](https://www.bse.cn/nq/listedcompany.html)和[上交所休市安排](https://www.sse.com.cn/disclosure/dealinstruc/closed/)人工复核。适配器使用的是这些页面背后的数据接口，接口参数和响应结构仍可能随网站改版变化。

## 行情选择与完整性门禁

腾讯和新浪不会按日期拼成一条混合序列。Provider 对每个候选依次执行：

1. 请求区间、日期格式、严格升序与无重复校验；
2. 不复权收盘价正数校验，或前复权 OHLCV 有限值与高低关系校验；
3. 过滤尚未完成的当日日线；
4. 在已有 official 日历的年份逐交易日核对内部缺口；
5. 用上市日与明确停复牌区间排除可解释的证券级空档；
6. 校验请求尾部为 `complete`、`confirmed_non_trading` 或 `incomplete`；
7. 两个来源都有候选时，对重叠日期收盘价执行一致性检查。

严格回测只接受：

- `complete`；或
- 日历独立证明尾部全部休市的 `confirmed_non_trading`；且
- 请求区间内没有 error 级别问题。

腾讯和新浪共同缺少同一内部区间、且两侧都有正常行情时，应用不会插值或伪造价格，只把缺口标为 `cross_provider_common_gap`，结果进入 `degraded` 并显著告警。单源缺口、头部截断、尾部缺失和跨源明显冲突仍阻断严格回测。对应实现见 [marketDataProvider.ts](../electron/data/marketDataProvider.ts)。

## 缓存、持久化与来源追踪

| 数据 | 生命周期 | 写入条件 |
| --- | --- | --- |
| 股票/ETF 目录 | SQLite 完整快照；成功获取后 7 天内复用 | 数量、类型、分页和唯一性检查全部通过；按资产类型原子替换 |
| 回测行情与公司行动 | 与不可变回测试验同一 SQLite 事务 | 所有标的严格校验和计算成功；任一步失败整批回滚 |
| 实盘行情 | SQLite 价格行 + 独立覆盖区间 | `data`、有独立日历证据的 `empty` 或带 error 详情的 `partial`；partial 后续重试完整原始区间 |
| 新浪全历史与复权因子 | 当前主进程内 Promise 缓存 | 请求成功；失败会删除内存缓存，允许后续重试；应用重启后失效 |
| 自动停复牌证据 | SQLite 证券级区间；按本次已确认覆盖范围更新 | 主源或备用源的传输、全分页、结构和日期覆盖全部通过；主源恢复时清理同范围旧备用证据，人工来源与范围外历史保留 |
| 年度交易日历 | 随应用打包的 JSON | 发布维护人工录入官方安排；构建脚本校验当前年度状态 |

数据库 Schema 版本仍固定为 `1`。结构定义见[schema.ts](../electron/storage/schema.ts)；目录 provenance、行情来源、兜底原因、覆盖状态与公司行动分别落库。数据库不读取 Labs 或 Research 的数据目录。本轮没有修改 DDL；只刷新 Schema 1 的契约指纹，使缺少结构化 `dataQuality` 的同版本旧库被明确拒绝，而不是从旧状态字段或警告文案猜测。没有迁移，也没有把版本提升到 2。

## 与 AKShare 的边界

- `package.json` 没有 AKShare 或 Python 运行依赖；Electron main 不启动 Python；
- 产品不调用 Lab 0 的 health check、Notebook 或缓存；
- Lab 0 的“识别真实上游、独立风险面、同语义降级”只作为经过评审的架构结论，产品在本域独立实现；
- 新浪 KLC 解码器参考了固定提交的 AKShare-TS MIT 实现，许可和提交链接记录在[THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。这属于代码来源声明，不是运行时 AKShare 数据源；
- 东方财富接口故障可能同时影响 AKShare 与本应用的主源直连适配器，因为两者共享真实上游；桌面端的百度备用实现独立直连其公开日历接口，不运行 AKShare。

## 验证与已知风险

默认测试不联网：

```powershell
npm run test:contract
```

发布前受控联网验证：

```powershell
npm run smoke:market-data
```

脚本见 [run-market-data-smoke.mjs](../scripts/run-market-data-smoke.mjs)，证据写入[market-data-smoke.json](../artifacts/market-data-smoke.json)。该文件中 `2026-08-08T03:36:51.660Z` 的 ETF 东财主源记录属于本次路由修改前的历史证据，不代表当前产品仍使用东财目录。本次修改后的不落盘实时验收执行于 `2026-08-08T07:19:16.912Z`：新浪 ETF 主源返回 1,624 只，东方财富新停复牌主源与百度独立备用源均对 `603221` 的固定区间返回 1 条证据，受控东财 HTTP 503 时自动切换百度并保留失败原因；全部七项设置页检查为 `available`。一次探测只证明当次请求，不构成持续可用承诺。

当前剩余风险按优先级排列：

1. **公司行动仍是东方财富单点。** 应在需要提高发布等级时引入公告或交易所来源的独立核验，但在语义未对齐前不能自动替换。
2. **百度备用的可验证结构化历史始于 2023-01-01。** 更早的回测范围在东财主源失败时只得到部分覆盖并明确告警；百度历史记录中没有复牌日的开放区间不会被猜测延长。
3. **腾讯、新浪、东方财富和百度均为未版本化网页后端。** 结构、分页和范围校验能阻止部分静默错误，不能保证持续可用；发布代码必须重新执行真实联网检查。
4. **现有持久化 smoke 证据尚未覆盖三家交易所股票目录、公司行动和新的停复牌主备端点。** 设置页不落盘健康检查已经覆盖这些能力，但发布门禁仍应后续合并为统一证据。
5. **ETF 目录现在是新浪单一门户源。** 数量门槛只能发现明显截断，不能证明每只基金的上市状态和分类完全准确；失败时保留旧完整快照，重要标的应回到交易所基金列表复核。
6. **无通用重试与退避。** 当前设计偏向快速失败和保留旧证据，避免在未知限流状态下放大请求；如增加重试，必须按来源分别限速并设置总时间预算。
7. **年度日历需要持续维护。** 2024—2026 为 official，2027 当前为`pending_official_schedule`；官方安排发布后必须更新 JSON，Schema 版本仍保持 1。
