## 结论

桌面产品是纯 Node.js/TypeScript 实现，不 import、执行或读取 Labs、Research、AKShare 或 Python。Labs 只提供已经评审的选源结论，产品在 `src/desktop` 内独立实现适配器、校验、缓存和来源追踪。

产品直接访问交易所公开接口以及腾讯、新浪、东方财富、同花顺和百度的网页后端。这些端点没有面向本产品的稳定版本契约或 SLA，因此所有响应都必须经过结构、分页、范围、数量、日期、数值和跨源一致性校验；设置页与发布 smoke 的状态只代表当次请求。

当前固定原则如下：

1. 沪深京 A 股目录由三家交易所公开列表合并，任一组成部分失败都不覆盖本地完整快照；
2. ETF 目录由新浪提供名称，沪深交易所官方目录负责成员校验、补全和新浪故障后的整段备用，官方目录本身失败时拒绝刷新；
3. A 股与 ETF 行情均使用腾讯主源、新浪整段备用，不按日期拼源，也不插值；
4. 股票公司行动合并东方财富与同花顺 F10 已实施记录，ETF 分红合并新浪累计因子与东方财富基金 F10；
5. 停复牌使用东方财富逐证券历史事件主源、百度股市通独立备用源，盘中事件、部分覆盖或未闭合备用记录不能成为完整证据；
6. 2011—2026 快捷回测区间使用内置官方年度休市安排，2027 保持 `pending_official_schedule`；
7. 数据源顺序是产品契约，不提供允许用户绕过完整性门禁的任意主备开关。

## 严格完整性门禁

腾讯和新浪不会按日期拼成混合行情。每个候选必须通过响应结构、日期单调且唯一、OHLCV 数值关系、请求首尾、官方交易日历缺口和上市/停牌证据校验；候选切换后重新执行同一门禁。两源共同缺少交易所应开市的日期且没有独立停牌证据时标记 `cross_provider_common_gap` error 并阻断，不再降级保存完成实验。

ETF 目录以沪深交易所官方合并集合为最终成员集合，新浪只覆盖其中名称。官方目录声明总数必须与实际分页一致，合并后不得少于 1,000 只；新浪与官方集合重合率低于 95% 时拒绝刷新。2026-08-09 的 smoke 为 1,600/1,600 重合。

股票公司行动先分别解析两源的已实施方案，再按除权日合并。两源同日记录必须在现金金额、送转比例和登记日上一致；唯一已评审例外是 `600900` 在 2016-07-19 的差异化分红，东方财富 0.12946 元/股对应特定资产认购股份，同花顺 0.40 元/股对应二级市场普通股，[巨潮正式公告](https://static.cninfo.com.cn/finalpage/2016-07-13/1202468389.PDF)证明本回测应使用 0.40 元/股，程序只在证券、日期、登记日、金额和送转比例组成的完整结构化指纹精确命中时校准并记录公告编号，0.35696 元/股的加权值只用于除息参考价而不是投资者现金。两源独有记录若相距七天以内则视为疑似日期语义冲突并阻断，避免同一事件重复入账；其余一方独有的已实施记录保留并披露计数，避免东方财富漏掉特别分红。ETF 分红采用相同原则，但不比较新浪累计因子无法提供的登记日，重合记录使用东方财富 F10 补齐登记日与发放日。

东方财富停复牌主源逐证券查询 `EVENT_TYPE_CODE=023`，只有正文中的明确日期与全天时段能成为缺口排除证据；盘中停牌不会被扩大为全天，开放事件可以保存到本次已观察截止日但不宣称最终复牌日。百度停复牌可验证结构化覆盖从 2023-01-01 开始；统一备用路由拒绝早于该日期的部分覆盖，也拒绝任何 `unresolvedOpenIntervals>0` 的结果。人工公告证据始终与自动来源分离并保留。

## 缓存、持久化与来源追踪

| 数据 | 缓存或持久化 | 写入条件 |
| --- | --- | --- |
| 股票与 ETF 目录 | SQLite 完整快照，成功后七天内复用 | 当前资产类型的全部来源和完整性门禁通过后原子替换 |
| 回测行情与公司行动 | 与不可变回测试验同一 SQLite 事务 | 所有标的行情、日历、公司行动和计算成功；任一步失败整批回滚 |
| 实盘行情 | SQLite 区间快照和覆盖表 | 数据、合法空区间或 partial 状态拥有明确 provenance |
| 自动停复牌证据 | SQLite 按来源和确认覆盖范围替换 | 主源或严格备用完整成功；失败不删除旧证据 |
| 人工停复牌证据 | SQLite 独立来源记录 | 用户依据公司或交易所公告补证；自动同步不得删除 |
| 年度交易日历 | 随应用打包的 JSON | 构建脚本验证当前年度及最大 15 年快捷区间状态 |

provenance 至少记录实际来源、约定主源、是否兜底、兜底原因、获取时间、数据截止日、复权口径和计算口径版本。数据库 Schema 仍为 1，不读取 Labs 或 Research 数据目录，也不从旧警告文案推断结构化质量状态。

## 可观测性与发布证据

设置页数据源检查覆盖八项实际能力，逐项返回 `available`、`degraded` 或 `unavailable`、固定路由、实际来源、延迟、数据截止日、详情与失败原因。检查由用户显式触发，不写入目录、行情、公司行动或停复牌缓存。

发布前运行：

```powershell
npm run smoke:market-data
```

脚本见 [run-market-data-smoke.mjs](../scripts/run-market-data-smoke.mjs)，持久化证据见 [market-data-smoke.json](../artifacts/market-data-smoke.json)。2026-08-09 12:55（Asia/Shanghai）的结果为八项全部 `available`：A 股 5,539 只，ETF 1,600 只且新浪与官方目录重合 1,600/1,600，股票分红双源重合 5 条并保留同花顺独有 1 条，ETF 分红双源重合 3 条，`600900` 在 2011-07-25..2026-07-24 的 17 条分红全部完成双源合并，其中 2016-07-19 差异化分红按巨潮公告校准为 0.40 元/股，东方财富和百度停复牌固定样本各 1 条；历史源命中 `601398`、`601857` 的五个报错停牌日，两只股票各自 15 年严格行情均为 3,640 行且 `errorIssues=0`。一次成功不构成持续可用承诺。

## 剩余风险

1. 未版本化网页后端和交易所公开接口都可能变更结构、风控或访问策略，必须在每次发布前重新运行联网 smoke。
2. 百度 2023-01-01 前不能承担完整备用，未闭合记录不能证明最终复牌日；严格失败和人工补证是有意的安全边界。
3. 公司行动单源独有记录虽不会再静默丢失，但重大研究结论仍应以公司或交易所正式公告复核；当前差异化分红官方校准仅覆盖已发现并评审的 `600900:2016-07-19`，未知个案仍会阻断而不是猜测适用权益。
4. 2027 官方休市安排尚未发布，保持 `pending_official_schedule`，不得提前猜测。
