# 攒股收息桌面端设计系统

> 状态：实盘记录主线设计基线
>
> 适用范围：`src/desktop/` 全部桌面页面
>
> 设计基准：1920 × 1080，中文桌面金融工作台
>
> 技术映射：React 18、Ant Design 5、Tailwind CSS、ECharts

## 1. 目标

本设计系统把 `ARCHITECTURE.md` 中的“冷白画布、深墨蓝信息层级与亮蓝单一动作色”扩展为可直接执行的界面规则。

设计系统解决跨页面一致性问题；每个页面的业务结构、字段、状态和交互仍由 `desktop_ui/*_ui_brief.md` 定义。

移动端券商截图仅用于参考信息分组、指标优先级和操作路径，不继承其移动端比例、暖色渐变、大卡片、广告位或红色主操作风格。

## 2. 设计原则

### 2.1 事实优先

- 每个金额、收益率、持仓和日期都应能追溯到数据来源或业务流水。
- 数据截止时间、估值时间和计算口径必须出现在用户能看见的位置。
- 不用装饰性图表掩盖数据缺失，不把“尚未加载”“无数据”“计算失败”统一显示为空白。

### 2.2 高密度但不拥挤

- 桌面端优先使用横向空间、表格、分栏和紧凑工具栏。
- 同层级信息保持统一字号、行高、间距和对齐方式。

### 2.3 单一动作色

- 亮蓝只表示可操作、选中、聚焦和链接。
- 金融涨跌色只表达收益方向，不承担按钮、链接和系统状态含义。
- 页面不得出现第二套金色、暖棕色、瓷白色或渐变品牌主题。

### 2.4 追加式记录

- 实盘流水是事实源，不以普通“编辑/删除”改写历史。
- 修正、冲正、撤销必须显示原记录与关联关系。
- 危险动作通过文字、二次确认和结果说明表达，不只依赖红色。

### 2.5 一致的工作台结构

所有一级业务页优先采用：

```text
页面标题与说明
→ 数据截止/更新时间与页面级动作
→ 关键指标或过滤区
→ 主数据区域
→ 详情、来源和异常说明
```

## 3. 桌面基线与框架

- 基准分辨率：1920 × 1080。
- 应用侧栏、56px 顶栏和主内容框架沿用现有 `AppShell`。
- 主内容区横向内边距：24–32px；纵向首尾内边距：16–24px。
- 页面板块间距：12px；大区块间距最多 16px。
- 主页面不使用浏览器式超长滚动；优先让表格、列表或详情区内部滚动。
- 1920 × 1080 下应完整看见页面标题、核心指标、主工具栏和至少 10 行主表格。

## 4. 颜色系统

### 4.1 基础颜色

| 语义 | Token | 色值 | 用途 |
| --- | --- | --- | --- |
| 主动作 | `brand` | `#1677FF` | 主按钮、选中态、焦点、主链接 |
| 主动作强调 | `brand-strong` | `#0D5DC3` | Hover、深色链接 |
| 强文字 | `text-strong` | `#112543` | 页面标题、核心数字、表格主值 |
| 正文 | `text` | `#1E3554` | 正文、表格内容 |
| 次文字 | `text-muted` | `#5D6F87` | 辅助信息、说明、时间 |
| 禁用文字 | `text-disabled` | `#98A6B8` | 禁用、不可用 |
| 页面画布 | `canvas` | `#F6F8FB` | 主背景 |
| 容器 | `panel` | `#FFFFFF` | 卡片、表格、Modal |
| 弱容器 | `panel-subtle` | `#F8FAFC` | 表头、分组、选中前背景 |
| 边框 | `stroke` | `#DFE6EF` | 输入框、容器主边框 |
| 弱边框 | `stroke-soft` | `#EDF1F6` | 表格行、组间分隔 |

### 4.2 系统状态

| 状态 | 色值 | 规则 |
| --- | --- | --- |
| 成功 | `#13A68F` | 保存成功、数据正常、连接正常 |
| 警告 | `#F5A623` | 数据过期、口径提醒、待确认 |
| 错误 | `#F04438` | 加载失败、校验失败、危险操作 |
| 信息 | `#1677FF` | 一般提示、帮助说明 |

### 4.3 金融语义

A 股语境采用红涨绿跌：

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| 正收益/上涨 | `#E5484D` | 正收益、正涨幅、收益日历正值 |
| 负收益/下跌 | `#13A68F` | 负收益、负涨幅、收益日历负值 |
| 持平 | `#60738F` | 零值、无变化 |
| 分红事件 | `#1677FF` | 分红标记、事件图标，不表示涨跌 |

规则：

- 金融颜色不得用于主按钮。
- 系统错误与正收益虽然都接近红色，但必须通过图标、文案、位置和组件语义区分。
- 表格和日历不得只靠颜色表达正负，必须同时显示符号或文字。

## 5. 字体与数字

字体沿用：

```css
-apple-system, BlinkMacSystemFont, "Inter", "PingFang SC",
"Microsoft YaHei", sans-serif
```

| 层级 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 24/32 | 700 | 一级页面名称 |
| 关键指标 | 24–28/32 | 600–700 | 总资产、收益等核心数字 |
| 区块标题 | 15/22 | 600 | 表格、图表、日历标题 |
| 正文 | 13/20 | 400 | 主要内容 |
| 表头/标签 | 12/18 | 500–600 | 表头、字段名 |
| 辅助说明 | 11–12/18 | 400 | 时间、来源、口径 |

数字规则：

- 金额、数量、价格、百分比统一使用 `tabular-nums`。
- 表格数字右对齐，日期和文本左对齐，短状态可居中。
- 人民币默认格式：`¥1,234.56`；表单可显示 `1,234.56 元`。
- 百分比保留两位小数；股数根据业务精度显示，不用视觉上无意义的尾数。
- 正值显示 `+`，负值显示 `-`，零值不显示正号。

## 6. 间距、圆角与阴影

采用 4px 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 表单字段间距：12px。
- 卡片内边距：16–20px。
- 表格单元格：纵向 9–10px，横向 12px。
- 小控件圆角：5–6px。
- 面板圆角：8px。
- Modal 圆角：10px。
- 页面不使用大面积浮层阴影；面板主要依靠边框区分。
- 阴影只用于顶部浮层、Modal、下拉菜单和主按钮的轻微层级。

## 7. 页面组件规则

### 7.1 页面标题区

- 左侧：页面标题 + 一行用途说明。
- 右侧：数据截止/估值时间、次级动作、唯一主动作。
- 同一页面最多一个实心主按钮。

### 7.2 指标区

- 默认使用一条横向指标带，不做独立的六张大卡片。
- 单个指标包含：字段名、主值、可选副值或口径说明。
- 指标之间使用弱分隔线，不使用不同背景色区分。
- 正负数使用金融语义色；资产总额等中性数据使用深墨蓝。

### 7.3 筛选工具栏

- 筛选项单行优先，复杂条件放“高级筛选”Drawer 或 Popover。
- 常用字段顺序：时间 → 标的 → 类型/状态 → 搜索 → 重置。
- 结果数量和更新时间放在工具栏右侧或表格标题右侧。

### 7.4 表格

- 表格是持仓与流水页面的主要信息载体。
- 表头背景 `panel-subtle`，不使用高饱和色。
- 行高以 40–46px 为主；双行单元格不超过 54px。
- 金额、比例、数量列右对齐。
- 固定首列和操作列只在横向空间不足时使用。
- 默认不使用斑马纹；Hover 使用极弱蓝色。
- 排序必须明确当前字段和方向。

### 7.5 Tag 与状态

- Tag 用于事件类别、来源和状态，不用于承载长文案。
- 买入、卖出、分红、修正和冲正分别使用低饱和背景。
- 危险状态不能只写“异常”，必须给出可执行说明。

### 7.6 Modal、Drawer 与详情

- 新增/修正操作使用居中 Modal。
- 记录或标的详情优先使用右侧 Drawer，避免离开当前上下文。
- Modal 表单底部固定显示取消与主动作。
- 涉及金额影响时，提交前显示“本次操作影响”摘要。

## 8. 图表与日历

### 8.1 图表

- 白色面板、浅灰网格、深墨蓝坐标文字。
- 单序列默认亮蓝；金融正负区域按红涨绿跌。
- 禁止使用面积渐变作为主要信息编码。
- 图例、时间范围、数据截止时间必须可见。
- Tooltip 中金额、收益率和日期使用统一格式。

### 8.2 收益日历

- 7 列自然周网格，周一至周日顺序固定。
- 正收益浅红底，负收益浅绿底，零收益白/灰底。
- 色阶最多 3 档，避免颜色深浅被误解为精确比较。
- 分红日增加蓝色小标记或图标；不以整格蓝色覆盖收益方向。
- 每个日期格显示日期和当日总收益；选中后在侧边详情区显示价格变动收益、分红和标的贡献。

## 9. 数据状态

每个数据区必须区分：

- `loading`：Skeleton 或表格 loading；
- `ready`：正常数据；
- `empty`：说明为何为空，并给出下一步；
- `stale`：保留数据但明确更新时间和刷新入口；
- `error`：说明失败范围，不清空其他可用数据；
- `partial`：明确哪些指标或标的缺失，不给出伪完整汇总。

空状态不得只写“暂无数据”，应说明例如：

- “尚未录入交易流水，无法重建持仓”；
- “当前月份没有收益记录”；
- “行情未更新，收益仍按 2026-07-24 收盘价估算”。

## 10. 交互与可访问性

- 所有按钮、行操作、日期格和图表切换必须支持键盘焦点。
- Focus 使用亮蓝 2px 外框。
- 图标按钮必须提供 Tooltip 或 `aria-label`。
- 不通过双击作为唯一操作方式。
- 删除、冲正、覆盖等动作必须二次确认。
- 成功与失败反馈使用 Message/Notification，关键错误在页面内保留 Alert。

## 11. 禁止项

- 不使用暖金、米黄、橙棕渐变作为资产卡背景。
- 不使用红色主按钮或红色导航选中态。
- 不复制手机端广告横幅、营销文案和大面积留白。
- 不把多个独立页面塞进一个无限滚动 Dashboard。
- 不用饼图代替可比较的精确表格；资产结构可用小型环图辅助，但表格仍是事实源。
- 不在 Renderer 重新计算领域指标。
- 不在缺少数据时显示 `0.00` 冒充真实结果。

## 12. Ant Design 与 CSS 映射

- Ant Design Token 是组件外观的唯一基线。
- CSS 变量承载跨组件语义颜色和布局，不在业务页面散落任意十六进制色。
- Tailwind 主要用于布局、间距和响应式辅助，不建立第二套颜色系统。
- 金融涨跌色使用独立类或语义变量，例如：

```css
--color-finance-up: #e5484d;
--color-finance-down: #13a68f;
--color-finance-flat: #60738f;
```

## 14. 视觉验收

- 1920 × 1080 下页面层级与历史回测一致。
- 主操作始终为亮蓝，金融涨跌不污染操作色。
- 页面没有暖色品牌卡、广告位或移动端大卡片复制。
- 所有金额和百分比对齐稳定，正负号与颜色一致。
- Loading、空、过期、错误和部分数据状态均有明确设计。
- 三个实盘页面在侧栏、页头、指标带、表格、Modal、Drawer 和提示组件上使用同一套规则。
