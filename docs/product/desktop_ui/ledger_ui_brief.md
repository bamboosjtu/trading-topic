# 交易流水 UI Brief

> 状态：已审定设计
>
> 页面入口：`实盘 / 交易流水`
>
> 设计基线：1920 × 1080，16:9；支持 3840 × 2160 等大屏自适应
>
> 依赖：[DESIGN_SYSTEM.md](../DESIGN_SYSTEM.md)

## 1. 页面目标

交易流水是 R1 实盘记录的唯一事实写入页，用于：

- 手工录入买入、卖出、分红、资金转入、资金转出和国债逆回购；
- 查询并核对历史记录；
- 通过追加式修正或冲正纠正错误记录；
- 为持仓明细、账户资产和收益日历提供统一事实源。

数据关系：

```text
交易流水（唯一事实源）
        ↓
持仓、成本、现金与累计分红重建
        ↓
持仓明细与收益日历只读展示
```

## 2. R1 边界

- R1 只有一个证券账户，不显示账户选择、账户编号或多账户汇总。
- 所有记录均为手工录入，不支持导入券商流水。
- 页面不要求用户填写流水号、订单号、委托号、成交编号、对方机构或精确录入时间。
- 交易时间只保留业务日期，统一格式为 `YYYY-MM-DD`，不显示时、分、秒。
- 数据库可以保留内部主键用于关联、排序和冲正，但内部 ID 不在界面、表单和用户导出中展示。
- 原记录不物理删除；错误通过修正或冲正处理，保留事实链路。
- 持仓和收益不得在本页由 Renderer 临时计算。

## 3. 信息架构

```text
应用顶栏

页面标题 + 用途说明                         数据截止日期  录入交易

筛选区

流水统计指标带

交易记录表格                              交易详情 Drawer

分页与事实源说明
```

详情 Drawer 关闭时表格占满主内容区；打开后表格自适应缩窄，不跳转页面。

## 4. 页面标题区

### 4.1 左侧

- 标题：`交易流水`
- 说明：`记录所有手动录入的交易与分红，持仓与收益按流水自动重建。`

### 4.2 右侧

- 数据截止：`数据截止：2026-07-26`
- 页面唯一实心主按钮：`录入交易`

规则：

- 不显示账户切换、导入流水或同步券商按钮；
- “录入交易”打开居中 Modal；
- 数据截止只精确到日期。

## 5. 筛选区

筛选区使用白色面板，单行优先，字段顺序固定：

1. 日期范围；
2. 交易类型；
3. 标的类型；
4. 标的；
5. 备注；
6. 重置；
7. 查询。

### 5.1 日期范围

- 使用 DatePicker RangePicker；
- 精确到日期；
- 默认显示有记录的最近合理区间，R1 可默认本年度；
- 允许清空后查询全部记录。

### 5.2 交易类型

可选：

- 全部；
- 证券买入；
- 证券卖出；
- 分红到账；
- 资金转入；
- 资金转出；
- 国债逆回购；
- 修正/冲正。

### 5.3 标的类型

可选：

- 全部；
- 股票；
- ETF；
- 其他适用于当前领域模型的证券类型。

资金转入、资金转出等无标的记录不受标的类型筛选误伤；筛选逻辑应明确处理“无标的”。

### 5.4 标的

- Placeholder：`名称/代码`；
- 支持名称和 6 位代码搜索；
- 不要求用户输入交易所后缀。

### 5.5 备注

- Placeholder：`关键词`；
- 匹配用户备注；
- 不搜索内部 ID 或系统元数据。

### 5.6 查询动作

- `查询`为蓝色主动作；
- `重置`为描边次级按钮；
- 查询条件变化不自动改写事实数据。

## 6. 流水统计指标带

筛选区下方展示单条横向指标带，默认统计当前筛选结果；若产品决定统计全部数据，必须在指标标题中明确“全部记录”。

从左至右：

1. 记录总数；
2. 累计买入（含费用）；
3. 累计卖出（含费用）；
4. 累计分红；
5. 资金净流入。

### 6.1 指标定义

- `记录总数`：当前筛选范围内有效记录数量；
- `累计买入（含费用）`：买入成交金额与买入费用共同纳入口径，主值表示实际资金流出；
- `累计卖出（含费用）`：卖出成交金额与卖出费用共同纳入口径，主值采用领域层定义的卖出净流入；
- `累计分红`：分红到账记录的金额合计；
- `资金净流入`：外部资金转入减外部资金转出，不把证券买卖或分红重复算作外部资金流。

### 6.2 视觉规则

- 指标带沿用历史回测和持仓明细的字体与密度；
- 金额使用 `tabular-nums`；
- 指标颜色用于区分类别，不代表涨跌，不使用大面积彩色背景；
- 任何汇总均由领域层或查询服务返回，Renderer 不自行重算。

## 7. 交易记录表格

标题：`交易记录`

默认排序：

1. 业务日期降序；
2. 同日记录按内部创建顺序稳定排序；
3. 内部排序键不显示给用户。

### 7.1 列定义

| 列 | 对齐 | 展示内容 | 说明 |
| --- | --- | --- | --- |
| 日期 | 左 | `2026-07-21` | 只显示日期，无时间 |
| 标的 | 左 | 名称；同行或次级文字显示代码 | 无标的记录显示 `—` |
| 交易类型 | 左/居中 | 低饱和 Tag | 证券买入、分红到账等 |
| 数量/份额 | 右 | `400`、`10,000` | 不适用时显示 `—` |
| 价格/份额 | 右 | `7.550` | 不适用时显示 `—` |
| 金额（元） | 右 | `3,020.00` | 业务金额，不显示无意义尾数 |
| 手续费（元） | 右 | `1.20` | 不适用时显示 `0.00` 或 `—`，口径保持一致 |
| 备注 | 左 | `长期持有` | 超长文本省略，Tooltip 显示全文 |
| 操作 | 居中 | 查看图标或 `查看` | 打开详情 Drawer |

### 7.2 Tag 规则

- 交易类型使用低饱和语义 Tag；
- Tag 仅用于分类，不使用红涨绿跌表达买卖；
- 建议：
  - 证券买入：浅红或浅暖色标签；
  - 证券卖出：浅蓝/中性标签；
  - 分红到账：浅绿色标签；
  - 资金转入/转出：蓝色或中性色标签；
  - 逆回购：紫色标签；
  - 修正/冲正：警告或错误语义标签。

### 7.3 行交互

- 单击行可选中；
- 点击“查看”打开右侧 Drawer；
- 双击不得作为唯一入口；
- 被冲正记录、修正记录和原记录之间应有可识别的关联标记；
- 不提供行内直接编辑或物理删除。

### 7.4 分页与滚动

- 默认 20 条/页；
- 可选 20、50、100 条/页；
- 表头固定，表体内部滚动；
- 1920 × 1080 下应完整展示约 10–14 行；
- 结果总数和分页位于表格底部右侧。

## 8. 交易详情 Drawer

详情 Drawer 从右侧打开，建议宽度 `380–460px`；在 4K 大屏上最大不超过 `520px`。

### 8.1 展示字段

通用字段：

- 日期；
- 交易类型；
- 标的；
- 数量；
- 价格；
- 金额；
- 手续费；
- 备注。

按类型增加：

- 资金转入/转出：资金金额；
- 国债逆回购：本金、到期日期、到期金额；
- 分红到账：分红金额；
- 修正/冲正：关联原记录及影响说明。

### 8.2 不展示的字段

- 流水号；
- 订单号；
- 委托号；
- 成交编号；
- 精确录入时间；
- 固定为“手动录入”的来源字段；
- 对投资分析没有作用的系统内部 ID。

### 8.3 底部动作

1. `编辑记录`：次级按钮；
2. `冲正此笔`：危险描边按钮。

“编辑记录”不是原地覆盖：

- 打开修正表单；
- 提交后追加修正记录或等价的追加式调整；
- 原始记录保持可追溯；
- 详情中显示修正关系。

“冲正此笔”：

- 二次确认；
- 生成与原记录相反影响的冲正记录；
- 不物理删除原记录；
- 已被完整冲正的记录不得重复冲正，除非领域规则明确允许。

## 9. 录入交易 Modal

点击“录入交易”打开居中 Modal。

### 9.1 基础结构

```text
录入交易

交易类型
业务日期
按类型动态出现的业务字段
备注

本次操作影响摘要

取消  保存记录
```

### 9.2 通用字段

- 交易类型：必填；
- 业务日期：必填，只精确到日期；
- 备注：选填。

不要求输入：

- 流水号；
- 录入时间；
- 来源；
- 账户；
- 对手方；
- 交易所后缀。

### 9.3 类型字段矩阵

| 类型 | 必填字段 | 可选字段 | 不适用字段 |
| --- | --- | --- | --- |
| 证券买入 | 日期、标的、数量、价格 | 手续费、备注 | 到期字段 |
| 证券卖出 | 日期、标的、数量、价格 | 手续费、备注 | 到期字段 |
| 分红到账 | 日期、标的、金额 | 备注 | 数量、价格 |
| 资金转入 | 日期、金额 | 备注 | 标的、数量、价格 |
| 资金转出 | 日期、金额 | 备注 | 标的、数量、价格 |
| 国债逆回购 | 日期、本金、到期日期、到期金额 | 备注 | 普通证券价格字段 |

修正和冲正不作为普通“录入交易”类型提供，必须从原记录详情发起，以保证关联关系。

### 9.4 自动计算与校验

- 证券买卖金额可由 `数量 × 价格`自动计算并只读展示；
- 实际资金影响由成交金额与手续费共同决定；
- 所有金额必须是有限非负数；
- 数量和价格必须满足领域精度；
- 卖出数量不得超过可卖持仓；
- 业务日期不得晚于允许的未来边界；
- 逆回购到期日期不得早于业务日期；
- 校验由领域层完成，前端校验只用于即时提示。

### 9.5 操作影响摘要

提交前显示：

- 现金增加或减少；
- 持仓增加或减少；
- 是否影响成本；
- 是否影响累计分红；
- 逆回购是否形成待到期资产。

该摘要只展示领域层预校验结果，不由 Renderer 自行推导第二套口径。

## 10. 手工录入与数据可信度

页面底部固定信息提示：

`所有数据均来自手动录入，请确保事实准确。持仓与收益按交易流水自动重建，不可直接修改持仓。`

原则：

- 手工录入是既定事实，不需要反复显示“来源：手动录入”；
- 记录是否可信主要依赖字段校验、追加式修正和可追溯关系；
- 不增加无分析价值的录入负担。

## 11. 数据状态

### 11.1 Loading

- 首次加载：指标带 Skeleton，表格 Loading；
- 查询切换：保留筛选条件，表格显示局部 Loading；
- 保存、修正和冲正期间禁用重复提交。

### 11.2 空状态

无任何流水：

- 标题：`尚未录入交易流水`；
- 说明：`录入首笔资金或证券交易后，系统将自动重建持仓与收益。`；
- 主按钮：`录入第一笔交易`。

筛选结果为空：

- 文案：`当前条件下没有匹配记录`；
- 提供 `重置筛选`；
- 不显示“录入第一笔交易”。

### 11.3 保存失败

- Modal 保留用户已填写内容；
- 显示明确错误原因；
- 不关闭 Modal；
- 不产生半条记录。

### 11.4 重建失败

流水保存成功但持仓重建失败属于严重一致性错误：

- 页面显示持续 Alert；
- 禁止展示伪完整持仓或收益；
- 引导重试重建或查看错误；
- 事实记录本身不得静默丢失。

## 12. 视觉规格

完全继承 `DESIGN_SYSTEM.md` 和历史回测页：

- 页面标题：24/32px，700；
- 指标数字：24–28/32px，600–700；
- 区块标题：15/22px，600；
- 正文与表格：13/20px；
- 表头：12/18px；
- 辅助说明：11–12/18px；
- 控件高度：32px，主按钮可使用 36px；
- 面板圆角：8px；
- 表格行高：40–46px；
- 主动作使用亮蓝，不使用红色主按钮；
- 页面不使用券商移动端的大卡片、营销区或暖色渐变。

## 13. 16:9 与大屏自适应

### 13.1 1920 × 1080

- 侧栏与 56px 顶栏沿用 AppShell；
- 主内容区横向内边距 24–32px；
- 筛选、指标带、表格在首屏完整出现；
- Drawer 打开后表格保留主要字段，必要时产生表格内部横向滚动；
- 页面本身不出现横向滚动。

### 13.2 3840 × 2160

- 字号、控件高度和表格行高不等比例放大；
- 主内容最大宽度建议 `2560–2880px` 并居中；
- 增加筛选字段间距和表格列宽；
- 使用更高可用高度展示更多记录，减少分页；
- Drawer 可增加到 480–520px，但不占据过多主表空间；
- 不通过新增无意义卡片填满屏幕。

### 13.3 较小窗口

- 最小逻辑宽度建议 1440px；
- 筛选区可换成两行，但字段顺序不变；
- 表格允许内部横向滚动；
- 标的列和操作列可固定；
- 不压缩字体至低于设计系统下限。

## 15. 验收标准

- 页面不存在账户切换、导入流水和流水号字段；
- 所有业务时间只显示到日期，不显示时分秒；
- “录入交易”是页面唯一事实写入入口；
- 普通录入不包含修正/冲正类型，修正必须从原记录发起；
- 表格完整展示日期、标的、类型、数量、价格、金额、手续费、备注和查看操作；
- 详情 Drawer 不展示内部 ID、固定来源或精确录入时间；
- 编辑采用追加式修正，不原地覆盖；
- 冲正生成关联记录，不物理删除原记录；
- 指标带展示记录总数、累计买入、累计卖出、累计分红和资金净流入；
- 所有汇总、持仓影响和收益影响由领域层返回；
- 1920 × 1080 下筛选、指标带和至少 10 行记录完整可见；
- 3840 × 2160 下保持字号与组件尺度，扩展列宽并显示更多记录；
- Loading、空、查询无结果、保存失败和重建失败均有明确状态；
- 页面视觉与历史回测、持仓明细保持同一冷白、深墨蓝和亮蓝动作体系。
