# 攒股收息 R1 桌面端 UI 设计评审与优化方案

> 评审范围：`src/desktop/renderer/src/pages/*`、`AppLayout.tsx`、`theme.ts`、`index.css`、`tailwind.config.ts` 及 `docs/product/desktop_ui/*` 设计简述。  
> 评审日期：2026-07-26  
> 评审视角：设计系统一致性、可访问性、信息层级、响应式与可维护性。  
> **结论**：当前 UI 在“历史回测”单页上形成了完整、专业且可辨识的投研工作站视觉语言；但整个项目存在两套相互冲突的视觉系统，且大量二级页面尚未接入或样式未定义。优化重点应放在统一设计系统、修复可访问性短板、补齐响应式断点上，而不是继续丰富单页动效。

---

## 1. 设计现状总览

### 1.1 已实现并运行的部分

- **全局壳**：侧栏（256px / 收起 72px）+ 顶栏（56px）+ 内容区（32px 水平内边距）。
- **历史回测页**：参数面板、6 项概览指标、ECharts 资产/收益/回撤曲线、标的对比表、回测明细 Modal。
- **骨架占位页**：其余 13 个路由入口全部渲染统一的 `SkeletonPage`。
- **设计语言**：冷白画布（`#f6f8fb`）+ 深墨蓝信息层级（`#112543`）+ 亮蓝单一动作色（`#1677ff`），贴合金融工作台审美。

### 1.2 两套并存的视觉系统（核心问题）

| 维度 | 系统 A：当前运行（冷蓝） | 系统 B：已写但未被路由引用（暖金） |
|---|---|---|
| 位置 | `theme.ts` + `index.css` 自定义类 | `tailwind.config.ts` 扩展色板 + `AccountPage/LedgerPage/SettingsPage` |
| 主色 | 亮蓝 `#1677ff` | 海军蓝 `#37799c` + 香槟金 `#c79345` |
| 中性色 | 冷灰蓝 `#75859b` / `#637691` | 暖瓷 `#a39e8d` / `#7b7668` |
| 构建方式 | 手写 BEM 类 + AntD 组件 | Tailwind 工具类（`page-eyebrow`、`metric-strip`、`text-gold-500`） |
| 状态 | 在 `BacktestPage` 中完整落地 | 三个页面均未被 `App.tsx` 路由引用，且部分类未定义 |

`AccountPage.tsx`、`LedgerPage.tsx`、`SettingsPage.tsx` 在 `renderer/src` 内仅出现各自的定义，没有任何 `import`；同时这些页面使用了 `page-eyebrow`、`metric-strip`、`metric-label`、`metric-value` 等类名，在 `index.css` 中并不存在。这意味着它们一旦接入路由，会立刻出现样式缺失或视觉错位。

**结论**：当前代码库内嵌了两套“意图不同、实现状态不同”的设计系统，是必须先解决的设计债务。

---

## 2. 优点（保持）

1. **专业、克制的金融视觉**：白色面板、浅灰背景、细线分隔、紧凑表格，符合投研工作台预期。截图中整体观感干净、有秩序。
2. **符合 A 股习惯的红涨绿跌**：回测明细与账户盈亏统一使用“盈利红、亏损绿”，减少用户认知成本。
3. **全等宽数字**：`tabular-nums` 在金额、百分比、代码列中一致使用，数值对齐可靠。
4. **可访问性基础已具备**：`focus-visible`  outline、`aria-current="page"`、按钮 `aria-label`、`prefers-reduced-motion` 媒体查询均已在代码中落地。
5. **骨架占位统一**：未实现页面使用一致的 `SkeletonPage`，避免“空白路由”或 404。
6. **Modal 上下文保留**：半透明灰蓝遮罩 + 固定高度 Modal，让背景中的参数和图表若隐若现，减少空间迷失感。

## 3. 问题与风险

### 3.1 设计系统一致性：P0

- **两套调色板冲突**：`theme.ts` 的冷蓝与 `tailwind.config.ts` 的暖金/瓷色在色相、温度上完全不同。未来任何页面如果同时引用两者，会出现“同一个 App 里两种品牌”的破碎感。
- **未定义类名**：暖系统页面中的 `page-eyebrow`、`metric-strip`、`metric-label`、`metric-value` 在 `index.css` 中无定义，接入后会出现无样式文本。
- **Tailwind 色板当前无用**：`navy`、`gold`、`ink`、`line` 等自定义色在 `BacktestPage` / `SkeletonPage` / `AppLayout` 中几乎未被使用，只是增加了维护者的认知负担。

### 3.2 可访问性：P1

使用 WCAG 2.1 对比度公式对关键文本/背景组合进行验证，结果如下：

| 文本颜色 | 背景 | 对比度 | 使用场景 | 判定 |
|---|---|---:|---|---|
| `#75859b` | `#fff` | 3.76:1 | 指标 caption、footer 说明 | 未达 AA 普通文本（4.5:1） |
| `#71839a` | `#fff` | 3.88:1 | 对比表 footer | 未达 AA 普通文本 |
| `#73839a` | `#fff` | 3.86:1 | 高级设置说明 | 未达 AA 普通文本 |
| `#8290a5` | `#fff` | 3.24:1 | 导航分组标签 | 未达 AA 普通文本 |
| `#1677ff` | `#fff` | 4.10:1 | 主按钮文字、链接 | 接近但未达 4.5:1 |
| `#1677ff` | `#f3f8ff` | 3.85:1 | 选中态/链接悬浮背景 | 未达 AA 普通文本 |
| `#c79345` | `#fff` | 2.73:1 | 暖系统 gold-500 | 未达 AA 大文本 |
| `#a39e8d` | `#fff` | 2.68:1 | 暖系统 ink-400 | 未达 AA 大文本 |
| `#112543` | `#fff` | 15.33:1 | 主标题/数字 | 优秀 |
| `#1e3554` | `#fff` | 12.41:1 | 表格正文 | 优秀 |

另外，回测明细 Modal 表格正文使用 `font-size: 9px`，小于可读性下限；即使对比度达标，过小的字号也会造成视觉疲劳和误读。

### 3.3 响应式与布局：P1

- `body { min-width: 1100px; overflow: hidden }` 与页面实际宽度不一致。以历史回测参数区为例：
  - 默认断点下网格列为 `minmax(430px,1fr) 390px 200px 260px 128px`，4 个 gap 共 64px，最小总宽 ≈ 1472px；
  - 内容区需加上侧栏 256px + 左右内边距 64px ≈ 1792px；
  - 即便 `@media (max-width: 1700px)` 下压缩到约 1214px，总宽仍约 1534px。
- 当窗口在 1100–1536px 之间（大量笔记本/外接显示器）时，`.app-content` 会出现内部横向滚动，体验不佳。
- 回测明细 Modal 固定 `width: 1000px` + `top: 23vh` + `height: min(730px, 100vh - 40px)`；在 720px 最小高度下，Modal 底部会超出视口。

### 3.4 交互与认知：P1–P2

1. **费用模式 Select 只有一项**：`Select` 中仅有一个选项“R1 简化费用（0 元）”。禁用/只读的 Select 会让用户误以为还有别的选项，建议改为只读文本或 `Tag` 展示。
2. **“最大”图表区间语义不清**：`chartRange` 的 `max` 实际触发 `yAxis.scale: true`，并不是时间区间。按钮文字“最大”会让用户误解为“最大时间范围”，建议改为“自适应”或单独作为 Y 轴缩放开关。
3. **顶栏两个入口指向同一页**：设置图标和“本地研究模式”下拉都导航到 `/settings`，属于重复 affordance。建议将头像/模式入口改为真正的用户菜单（设置、关于、退出）或移除其中一个。

### 3.5 可维护性：P2

- `index.css` 超过 1300 行，充斥大量手写魔法数字（`14px 20px`、`12px`、`9px`、`5px` 等），没有 CSS 变量或 spacing token 做约束。当前只有一页时可控，但后续扩展页面会迅速失控。
- `BacktestPage.tsx` 单文件约 1000 行，混杂了业务计算、图表配置、表格渲染、Modal 渲染。建议后续把配置区、指标区、图表区、表格区拆成独立组件，便于独立调整样式与测试。

## 4. 优化方案（按优先级）

### P0：统一设计系统，清理设计债务

1. **选定唯一系统**：以当前运行的冷蓝/墨蓝系统为正式系统，因为它已有完整截图和实现；废弃/冻结暖金系统。
2. **对齐 Tailwind**：如果保留 Tailwind 作为布局工具，将 `tailwind.config.ts` 的自定义色板移除或映射到与 `theme.ts` 一致的 token（如 `navy-500` → `#1677ff`、`ink-900` → `#112543`），禁止引入新的暖色。
3. **删除/重定向未接入页面**：
   - 若账户、流水、设置功能尚未开发，建议把 `AccountPage.tsx`、`LedgerPage.tsx`、`SettingsPage.tsx` 从源码中移除或移入 `__wip` 目录，避免误导。
   - 若已接近完成，则必须在接入路由前补齐 `index.css` 中缺失的 `page-eyebrow`、`metric-strip` 等类，或改用已定义的 `page-heading` / `backtest-metric` 风格重写。
4. **文档同步**：在 `docs/product/desktop_ui/` 设计简述中统一说明“所有页面使用冷蓝系统，禁止暖金/ink/gold 色板”。

### P1：可访问性修复

1. **提升辅助文字对比度**：
   - 将 `#75859b`、`#71839a`、`#73839a`、`#8290a5` 等统一加深一档，例如 `#5d6f87` 及以上（对比度 ≥ 5.0:1）。
   - 主色用于普通文本时，改用深蓝 `#0d5dc3` / `#095ed0` 以确保 ≥ 4.5:1；保留 `#1677ff` 用于按钮背景、图标或大块 UI 元素（3:1 即可）。
2. **最小字号约束**：
   - 页面标签/说明：≥ 11px（建议 12px）；
   - Modal 表格正文：≥ 11px，不再使用 9px；
   - 表头、按钮、导航项：≥ 12px。
3. **表单焦点**：已为 `button`/`a`/`[role=button]` 设置 `focus-visible`；建议为 `input`/`select` 等表单元素也补充一致的聚焦环（当前依赖 AntD 默认蓝色，尚可，但需确认与自定义色一致）。

### P1：响应式断点重设

1. **窗口最小宽度**：将 `body { min-width: 1100px }` 提升至 `1280px` 或 `1360px`，与参数区实际宽度对齐；或让参数区在 < 1360px 时折行到 2 行。
2. **参数区网格**：
   - 默认（≥ 1440）：一行 5 列；
   - 中屏（1280–1440）：折为“标的选择+回测区间”一行，“每月投入+费用模式+开始回测”另一行；
   - 小屏（< 1280）：单列堆叠，适合窄窗口。
3. **Modal 响应式**：改为 `width: min(1000px, 90vw)`、`max-height: 85vh`，取消固定 `top: 23vh`，让 Modal 在高度不足时自动适配。
4. **对比表**：保留 `scroll={{ x: 1120 }}`，这是合理的密集表格策略；确保表头固定和横向滚动指示器明显。

### P2：UX 细节优化

1. **费用模式**：改为只读文本展示：`费用模式：R1 简化费用（0 元）`，右侧用 `InfoCircle` 图标提示口径，节省空间并降低误解。
2. **“最大”区间按钮**：改为 `Y 轴自适应` 或拆成独立开关，避免与时间范围混淆。
3. **顶栏菜单**：保留一个设置入口；若需要用户菜单，则将其扩展为包含“设置、数据截止说明、退出”等真实选项，而不是直接跳设置。
4. **动态图表标题**：切换“收益率曲线/回撤曲线”时，标题跟随变化（“资产曲线对比”→“收益率曲线对比”），强化当前视图语义。
5. **空状态**：当无回测结果时，ECharts 区域显示明确占位提示，而不是空白坐标系。

### P2：设计 token 与组件化

1. **提取 CSS 变量**：在 `index.css` 顶部定义 `--space-*`、`--radius-*`、`--color-text-*`、`--color-surface-*`，让手写样式从变量取值。
2. **映射到 Tailwind**：将 Tailwind 的 `spacing`、`colors`、`borderRadius` 映射到同一套变量，允许在新页面中安全使用 Tailwind 工具类。
3. **拆分 `BacktestPage`**：
   - `BacktestConfig.tsx`：参数区；
   - `BacktestMetrics.tsx`：指标卡；
   - `BacktestChart.tsx`：图表与工具栏；
   - `BacktestComparisonTable.tsx`：对比表；
   - `BacktestDetailModal.tsx`：明细 Modal。

### P3：长期增强（可选，不影响 R1）

1. **暗色模式**：通过 `antd` 的 `algorithm.dark` + CSS 变量实现，可提升长时间盯盘体验。
2. **键盘快捷键**：如 `Ctrl/Cmd + Enter` 开始回测、`Esc` 关闭 Modal。
3. **数值提示**：在指标卡上增加 `Tooltip` 解释 XIRR、最大回撤、最长亏损时间的口径。

## 5. 实施顺序建议

| 阶段 | 任务 | 影响面 | 验收点 |
|---|---|---|---|
| 1 | 统一设计系统：移除/冻结暖金色板，清理未接入页面，补齐缺失类或删除文件 | 全局 | 全局无 `gold`/`ink`/`navy` 自定义色残留；所有路由可正常渲染无样式缺失 |
| 2 | 可访问性：修复对比度、提升最小字号 | `index.css`、图表 tooltip、Modal 表格 | 关键文本对比度 ≥ 4.5:1；Modal 表格最小 11px |
| 3 | 响应式：重设 min-width、参数区折行、Modal 适配 | `index.css`、`BacktestPage` | 1280px 窗口无横向滚动；720px 高度 Modal 不溢出 |
| 4 | 组件化与设计 token：拆 `BacktestPage`，提取 CSS 变量 | `renderer/src` | 单文件 < 200 行；新页面能用变量/工具类复现视觉 |
| 5 | UX 细节：费用模式、图表标题、空状态、顶栏菜单 | 页面级 | 用户测试无认知卡点和反馈 |

---

## 6. 需要用户决策的事项

1. **暖金系统是否保留？** 如果它来自早期探索，建议直接删除；如果未来品牌希望走暖色，则需要把 `BacktestPage` 也迁移过去，工作量较大。
2. **窗口最小宽度**：是否接受 1280px 作为最小窗口？对于低分辨率用户，需要确保窗口默认尺寸不低于该值。
3. **Modal 表格密度**：是否必须一屏显示 20 条？如果改为 12 条/页 + 更大字号，会牺牲“一屏看完”的设计目标，但会提升可读性。

---

**总体判断**：当前 UI 在单一页面上已经达到了可用、专业的水准，但尚未形成“可扩展、无障碍、可维护”的设计系统。下一步应优先解决“两套系统”和“可访问性”问题，再进入新页面开发与动效打磨。
