# 攒股收息 PRD

> 更新日期：2026-07-30
>
> 目标形态：单机 Electron 桌面应用
>
> 数据范围：回测为 A 股股票；实际投资记录为 A 股股票和境内交易所 ETF
>
> 数据截止日：每次计算均随结果记录，不在文档中写死

## 1. 目标

1. 用户能按明确口径回测一只或多只 A 股股票的固定金额攒股方案；
2. 用户能通过手工投资事实研究真实股票与 ETF 的持仓和收益。

成功标准是“结果算得对、来源说得清、数据拿得走”，不是功能数量。

## 2. 目标用户与核心场景

目标用户是低频交易、愿意手工维护关键流水的 A 股长期投资者。

核心场景：

- 创建固定区间或快捷区间的单标的回测；
- 从全 A 股代码表选择最多 10 只股票，以完全相同条件分别回测并排比较；
- 重新打开应用后继续使用上次退出时的参数、图表和当前实验；
- 查看每次运行生成的不可变历史实验，并导出当前实验的 XLSX 审计工作簿；
- 录入真实买入、卖出与现金分红事实；
- 查看当前持仓市值、投入、已实现与未实现收益、总收益和 XIRR；
- 导出 JSON 备份或日志，在本机恢复并复核。

## 3. 需求范围

### 3.1 历史回测

> 核心问题：过去按固定金额持续买入某个标的或组合，结果怎么样？

#### 标的与比较

- 只支持 A 股股票；
- 支持单标的回测；
- 支持最多 10 个标的同条件并排；
- 标的选择器通过产品自有 Node.js 适配器取得全 A 股代码与名称，并把成功快照缓存到本地；
- “并排”表示每只股票使用独立虚拟账户分别运行，不做组合、再平衡或跨标的资金共享。

#### 投入与买入规则

- 每月投入固定金额；
- 用户指定每月买入日；
- 指定日不是交易日时，顺延到其后的首个交易日，允许跨自然月；
- 回测请求从月中开始且当月指定日已经过去时，不补投请求起点之前的当月计划；
- 首个可用行情月份之前不生成投入计划，也不把股票上市前的月份累计到上市日；
- 首个可用行情月份内若指定日早于首个行情日，当月只在首个可用行情日投入一次；
- 每个自然月的投入计划独立执行：上月计划跨月顺延后，不占用也不取消下月计划；两个计划落在同一交易日时合并执行，但累计投入必须包含两个月；
- 只有从该月指定日至回测结束均没有后续交易日时，该月才不买入，并在结果中标记；
- 允许买入零碎股，内部股数保留足够精度，界面默认显示两位小数；
- 每月外部投入在执行日按当日收盘价全额买入，不因一手门槛保留现金；
- 买入价格统一采用实际执行交易日的收盘价；
- 每个并排标的独立结转现金，互不挪用。

#### 分红与公司行动

- 现金分红按登记日持股数量计算；
- R1 按数据源提供的除权除息/到账口径入账，结果中记录采用的事件日期字段；
- 分红现金在事件日加入对应虚拟账户，并按当日收盘价全额回购原标的；
- 送股、转增按登记日持股数量和“每 10 股送转股数”计算，在除权日增加持股；
- 公司行动适配器先删除完全重复记录，再用数据源方案 ID、报告期或方案公告日识别同一方案；同一方案只保留最终已实施版本，只有能明确识别为不同方案时才允许同日累加；
- R1 不参与配股、不追加配股资金；产品必须从独立配股数据集识别并逐项报告实际计算区间内、且不晚于共同数据截止日的事件、登记日、除权日、配股比例和认购价；
- 配股的市场除权影响由不复权价格自然反映并计入收益率与回撤，不得把“不参与”处理为“事件不存在”；其他无法识别处理口径的公司行动仍须阻断实验。

#### 简化费用

R1 只有一种费用模式，不提供多模型切换：

- 回测买入费用固定为 0；
- 印花税、分红税、过户费和滑点不计；
- 期末资产按市值估算，不假设卖出；
- 费用口径必须显示在结果页和导出文件中。

#### 区间

- 固定区间：用户选择开始日期和结束日期；
- 快捷区间：基于数据截止日提供预设年限；
- 快捷区间的具体选项由界面配置，但最终都转换为明确的开始日期、结束日期和数据截止日；
- R1 不做滚动窗口回测。

#### 输出

每个标的必须输出：

1. 累计投入；
2. 最终资产；
3. 累计盈亏；
4. XIRR；
5. 最大回撤；
6. 累计分红；
7. 期末现金。

口径：

- 最终资产 = 期末持仓市值 + 期末现金；
- 累计盈亏 = 最终资产 - 累计投入；
- XIRR 仅把每次月度外部投入记为负现金流，把期末资产记为正现金流；分红属于账户内部现金流，不重复计入；
- 最大回撤基于剔除外部投入影响的标的总收益净值序列计算，送转和现金分红均纳入收益口径，避免后续投入抬高总资产而掩盖真实跌幅；
- 最大回撤记录最深跌幅对应的峰值日和谷值日；“最长亏损时间”独立扫描全部回撤周期，记录持续最久一次的起止日及是否恢复，两者不得混用；
- 累计分红按实际入账金额累计，不因后续回购而减少。

并排结果必须同时展示各标的的数据来源、实际计算区间和截止时间。各标的保留各自首个可用行情日；实际起始日不一致时，必须明确标记“非严格同区间比较”，不得把请求区间相同表述为实际样本区间相同。

行情 K 线是辅助浏览能力，不属于严格回测证据。它使用独立获取的前复权真实日 OHLCV；日 K 直接展示，周/月 K 由真实日线聚合。新实验执行期间若数据源
报错、限流、响应结构损坏或出现异常年度缺口，必须终止实验；已保存的历史实验若缺少 K 线快照则显示明确原因。任何情况下都不得用回测收盘价伪造开盘、最高和最低价。

不复权价格和前复权 K 线统一返回 `requestedThrough`、`dataCutoff`、`tailStatus`、`issues` 与 provenance。腾讯和新浪必须分别通过相同的尾部校验。严格回测只接受 `complete` 或由独立交易日历确认的 `confirmed_non_trading`；任何 `incomplete` 都必须在计算和保存前终止，不生成 `completed` 实验。实盘查看可暂存两源中截止日较新的不完整结果，但必须显示 `partial` 并在后续继续补齐。交易所休市只能由年度官方日历证明；个股停牌不能由行情空响应推断，R1 在没有证券级停牌证据时保持 `incomplete`，不沿用前收盘伪造交易日价格。

回测明细必须区分：

- 本期外部投入与累计外部投入；
- 定投买入成交金额、分红回购成交金额与累计买入金额；
- 现金分红到账、分红回购、送股/转增入账三类事件。

每次点击“开始回测”必须创建一个新的不可变回测试验。同一次点击选择的多个标的属于同一个实验；相同参数再次运行也创建新实验，不更新或覆盖历史实验。

“回测结果对比”只展示当前实验的结果，因此其中所有行天然具有相同的区间、每月投入、买入规则、分红口径、数据截止时间与计算口径版本；表格只比较不同标的，并按 XIRR 降序排列。不得把其他历史实验的结果混入当前对比。

当前实验支持导出 `.xlsx`：第一个 sheet 为本次实验的对比结果，其余 sheet 为每个标的的逐笔明细，例如 `建设银行_三年`。

#### 回测对象模型

R1 只定义三个概念：

1. **回测请求**：用户当前填写的标的、区间、每月投入、买入日、分红处理方式和口径版本；它只是输入参数，不提供策略管理；
2. **回测试验**：每次执行生成的不可变记录，包含 `experimentId`、`createdAt`、 `request`、`results[]`、`dataCutoff`、`caliberVersion` 和 `status`；
3. **当前工作区**：只保存 `activeExperimentId`、当前图表 Tab、K 线标的、K 线周期和表单参数，不复制实验结果。

数据流固定为“回测请求 → 执行生成回测试验 → 工作区引用当前实验”。

### 3.2 实际记录

> 核心问题：我实际买了什么、投入了多少钱、现在赚了多少？

用户手工记录：

- 股票或ETF买入；
- 股票或ETF卖出；
- 现金分红到账；
- 追加式冲正/修正。

买入只需输入：

- 标的；
- 日期；
- 买入价格；
- 实际数量/份额；股票买入可提示通常按 100 股整数倍，但不得阻断零股、ETF 份额或修正事实；
- 实际费用可选修改。

卖出按实际股数/份额记录，允许清仓零股，但不得超过截止业务日的有效持仓。

快捷操作“分红并再投入”一次收集分红到账与随后买入信息，并在同一SQLite 事务内写入一条分红事实和一条买入事实。两条事实共享关联编号、可独立审计；任一写入失败时整体回滚。买入支出超过分红金额的部分直接体现在累计净投入中，不创建其他事实。再投入日期不得早于分红到账日，同日到账并再投入允许；保存前必须由领域层原子预览两条事实的合并影响。

现金分红到账只使用一个核心业务日期：`businessDate` 即到账日，不再维护另一套可与业务日期不一致的 `paymentDate`。买入和卖出必须发生在有效交易日；周末和独立交易日历确认的法定休市日直接拒绝；标的当日没有本地行情只说明“可能停牌或行情缺失”，必须警告并允许用户依据真实成交凭证继续录入，同时将该日标为待补行情的数据质量问题。分红到账可以发生在非交易日。

系统自动补充：

- 标的名称和行情；
- 当前市值；
- 历史分红信息；
- 预计分红；
- 登记日持股数量。

用户可以修改自动数据，最终以用户确认值为准。

实际记录核心输出：

- 当前持仓市值；
- 累计买入支出；
- 累计卖出净收入；
- 累计净投入；
- 未实现收益；
- 已实现收益；
- 累计分红；
- 投资总收益；
- XIRR。

投资收益使用证券投资现金流口径：

- 累计买入支出 = 买入成交金额 + 买入费用；
- 累计卖出净收入 = 卖出成交金额 − 卖出费用；
- 累计净投入 = 外部买入支出 − 累计卖出净收入 − 外部分红收入；
- 投资总收益 = 当前持仓市值 + 累计卖出净收入 + 累计现金分红 − 累计买入支出；
- XIRR 只投影投资者与证券投资组合之间的外部现金流：独立买入及关联买入超出可用分红的部分为负现金流，卖出净收入和独立分红为正现金流；关联分红及其再投入属于组合内部循环。期末资产为持仓市值加待再投入分红现金。

持仓页只读展示“待再投入分红”。R1 不提供“投资总收益率”这个简单比率。累计净投入会随卖出和外部分红回收而缩小、归零或转负，不适合作为普通收益率分母；跨日期现金流统一使用 XIRR，短期区间表现使用领域层返回的各期间收益率。

已清仓标的与当前持仓使用同一套现金流规则。分红再投入先确认一次分红收益，随后买入仅改变持仓与投资支出，不重复确认收益。收益归因按关联组维护“待再投入分红现金”：到账增加内部投资现金，关联买入优先消耗，超出部分才是外部新增投入，未使用余额跨日作为投资资产。日度资本基数为“期初持仓市值 + 期初待再投入分红现金 + 当日外部新增投入”；同日新到账分红只作为当日收益，不重复加入当日分母。

修正采用历史重述：`businessDate` 是投资事实日期，`recordedAt` 是 UTC录入时间，`correctedAt` 是修正操作时间。所有当前和历史分析都使用最新有效版本并投影到事实原业务日期；原记录、修正和冲正记录完整保留用于审计。修正关联事实时必须保持组内同一标的、同一资产类型、分红日期不晚于买入日期，并保证最多一个有效分红和一个有效买入；普通修正不能静默改变或新建关联。

### 3.3 基础能力

- 本地存储：业务数据默认只保存在本机 SQLite；
- 工作区恢复：标的、参数、图表选项和 `activeExperimentId` 由工作区 Hook 统一保存在 SQLite，重启后恢复；首次读取失败时暂停自动保存并显示“工作区加载失败”，用户可以重试或明确进入默认工作区；保存失败时捕获错误并明确告知用户；若活动实验不存在或无法读取，界面明确报错并清除失效引用，不自动打开其他实验；
- 证券目录缓存：沪深京全 A 股与境内交易所 ETF 分页代码表分别通过完整性校验后保存在 SQLite，并显式保存 `stock / etf` 类型；刷新失败时只回退到上次成功的完整快照，不以单页、少量默认标的或股票目录冒充 ETF 目录；ETF 目录同时保存实际来源、约定主源、是否兜底、兜底原因和获取时间；
- 来源追踪：行情、分红和估值结果记录实际来源、主源、备用源切换原因、获取时间、数据截止时间、复权方式和口径版本；
- JSON 备份：只导出当前 Schema 2，包含当前发布 fingerprint、schema 版本、导出时间、业务数据和全部必填元数据；
- JSON 恢复：只接受当前 Schema 2 的完整备份；在覆盖事务前校验完整流水引用图与领域归约、回测试验和结果、行情价格与覆盖区间、公司行动、证券目录及工作区引用。旧版本、非法引用、非法数值、缺失设置、资产类型、目录 provenance 或工作区字段的备份直接拒绝，不迁移、不补默认值；覆盖前先生成当前数据的安全备份并由用户确认；
- 日志导出：导出运行日志和错误上下文，不包含 Token、Cookie、账号或个人敏感信息；
- 不执行交易：不接券商、不下单、不请求交易权限，界面明确提示“仅供研究与记录，不构成投资建议”。

实盘业务日期按 `Asia/Shanghai` 的 A 股市场自然日生成；录入时间继续保存为UTC 时间戳。买入、卖出和现金分红的业务日期不得晚于当前市场日期。所有持仓和收益归约都接受显式截止日，只处理不晚于该日期的有效事实。

估值统一使用最近已完成交易日的正式收盘价：交易日 15:10 前使用上一交易日；15:10 后且行情完整才使用当日；周末、节假日使用上一交易日；历史月份使用
该月最后一个有效交易日。当日只有交易事实但没有正式收盘价时，收益归因标记不完整，不使用昨日价格冒充当日收盘价。

实盘查询必须区分 `factAsOfDate` 与 `valuationCutoff`：前者决定纳入哪些投资事实，后者决定正式收盘估值能计算到哪一天。估值截止日之后、事实截止日之前的买卖仍展示并参与持仓数量归约，但市值、投资总收益和对应日度归因返回`null / partial`，不得以前一交易日收盘价给新增持仓生成正式收益。

产品使用独立行情覆盖记录保存每次已成功检查的请求区间，包括合法空区间。春节、国庆等工作日休市区间只有在腾讯与新浪均明确成功返回空，且独立交易日历确认整个区间没有交易日时，才保存空覆盖并停止重复请求。腾讯失败而新浪返回空、HTTP、限流、结构损坏或异常候选行情都必须保持失败和待重试，不得写成空覆盖，也不得据此把正常交易日认定为休市。

行情以腾讯为主源；腾讯超时、HTTP 错误、结构或数据校验失败时，由新浪重新获取同一完整请求区间，不拼接两源区间。两源可用重叠日期必须执行一致性校验，明显冲突时停止计算并报告错误。

年度交易日历按年度 JSON 管理生命周期：`official` 表示已录入官方休市安排，`pending_official_schedule` 表示安排尚未发布且不得猜测。当前年度不是 `official` 时 CI/发布构建失败；已安装应用仍须正常启动并显示全局高可见告警，流水、历史结果、已结束月份、JSON 备份、日志、设置和诊断保持可用，仅阻断依赖缺失年度日历的行情补齐、日期确认与新回测。设置页展示每个年度的状态和来源。官方安排发布后，发布维护必须更新对应年度 JSON。

应用没有跨领域统一“数据截止日”。当前实验、持仓估值、收益日历与证券目录分别展示自身的截止或更新时间；顶栏只显示本地模式和应用版本。

首要流程：

1. 用户选择标的与区间并输入月度金额、买入日；
2. 系统校验数据完整性和公司行动支持范围；
3. 核心库计算并返回结果、口径、来源和告警；
4. 系统把同一次点击的全部标的结果保存为一份不可变实验，并设为当前实验；
5. 用户可在“历史结果”查看实验、复制参数重新运行或删除，也可导出当前实验的汇总和逐项明细 XLSX；
6. 实际投资分析始终从有效事实重算，不从回测结果自动生成交易。

## 5. 非目标

R1 不包含：

- 境外 ETF、场外基金、港股、美股或其他市场；R1 实际投资记录支持 A 股股票和境内交易所 ETF，历史回测仍只支持 A 股股票；
- 组合回测、再平衡或跨标的资金共享；
- 滚动窗口；
- 精确费用、分红税分档、滑点模拟；
- 券商账户余额、资金调拨或其他账户级资产管理；
- 预测型分红提醒、估值分位或选股建议；
- 移动端、Web 端、云同步或跨设备自动同步；
- 自动导入券商对账单；
- 券商连接、实盘下单或交易建议。
- 旧数据库迁移、旧备份恢复、缺字段旧事实推断或任何向后兼容层。

## 6. 验收标准

### 回测

- [ ] 给定同一输入快照，重复运行结果完全一致；
- [ ] 指定日遇周末、节假日时顺延到后续首个交易日；跨月顺延不占用下月投入，同日落入多个计划时累计金额正确；
- [ ] 请求早于股票首个可用行情月份时，上市前月份不生成也不累计计划；首个可用月份只执行一次当月投入，上市后的停牌计划仍可跨月积压；
- [ ] 每笔定投和分红回购都允许零碎股，现金余额不为负；
- [ ] 分红入账、回购、送股/转增和累计分红可逐笔追踪；
- [ ] 七项输出能由交易流水和日度资产序列重算；
- [ ] 多标的并排与分别运行单标的的结果一致；
- [ ] 可以按名称或 6 位代码检索全 A 股，单次选择不超过 10 个标的；
- [ ] 每次点击都创建新实验，相同请求重跑不会覆盖已有实验；
- [ ] 当前对比只包含当前实验内的标的，且按 XIRR 排序；
- [ ] 历史结果明确展示最近 500 次实验，可查看只读结果、复制参数重新回测和删除；更早实验不会因列表上限被删除；
- [ ] 应用重启后恢复上次标的、参数、图表选项和当前实验；
- [ ] 工作区首次读取失败时不写入默认参数，可重试读取或由用户明确选择默认工作区；
- [ ] 四标的实验在数据库关闭重开后，工作区、结果、收益/回撤序列、前复权 K 线和逐笔明细仍完整可读；
- [ ] XLSX 包含当前实验的对比汇总 sheet 和每个标的的完整明细 sheet；
- [ ] 合法空响应与限流、错误结构、行情异常缺口可区分；异常响应不会生成实验或修改回测行情缓存；
- [ ] 腾讯和新浪均执行尾部校验；严格回测遇 `incomplete` 时终止且数据库没有新增 `completed` 实验；
- [ ] 配股事件逐项报告“不参与”假设，其除权后价格变化仍进入收益和回撤；其他无法处理的公司行动不会被静默忽略；
- [ ] 产品使用位于 `src/desktop/` 内的自有 fixture 完成 golden tests；fixture 可源自已评审研究，但测试运行时不得读取或 import `research/`。

### 实际记录

- [ ] 普通录入只提供买入、卖出和现金分红；冲正/修正只能从原记录详情发起；
- [ ] 不存在其他账户事实时仍能由投资现金流重建完整收益；
- [ ] 当前持仓与已清仓标的使用同一套买入、卖出、分红和期末估值规则；
- [ ] 分红并再投入原子写入两条关联事实，分红收益只确认一次；
- [ ] 分红事实日期等于到账日；再投入不早于到账日，保存前可预览两条事实的合并影响；
- [ ] 跨日再投入等待期间的分红现金持续进入资本基数；1,000 元持仓、100 元分红、次日股价 10→11 的两日累计收益为 20%；
- [ ] 买卖的周末与交易所法定休市日被拒绝；标的无行情时明确警告但允许依据成交凭证继续，分红可在非交易日到账；
- [ ] 冲正/修正不修改原记录，并以最新有效事实历史重述原业务日期；
- [ ] 关联修正不能破坏同标的、同资产类型、日期顺序及“一分红一买入”组约束；
- [ ] 待再投入分红同时进入区间资本基数、期末 XIRR 资产和只读指标，且不减少外部净投入；
- [ ] 收益日历满足“总收益 = 市场价格收益 + 分红收益 + 交易影响”；
- [ ] 历史完整月份不因距今天较久进入 stale；
- [ ] 估值与导出显示实际行情源、备用源原因、正式截止日和复权方式；
- [ ] 腾讯失败时新浪可整段兜底；跨源明显冲突时阻断收益计算。
- [ ] 今日事实晚于正式估值截止日时仍展示事实和持仓数量，但市值、总收益与当日归因进入 partial；
- [ ] 买入前缓存行情不生成零收益日历日期；只有双源明确为空且交易日历确认的休市区间可持久化，主源失败与备用源空响应不会写入覆盖。

### 本地能力

- [ ] 断网时可查看既有数据并执行基于本地快照的计算；
- [ ] JSON 导出后可在空数据库恢复，恢复前后核心汇总一致；
- [ ] 只接受带当前指纹的 Schema 2 数据库；旧版本、同版本旧结构或指纹不匹配时保持原文件不变并阻止启动，不迁移、不自动清空；
- [ ] 不兼容、引用失真或领域非法的备份在覆盖事务前被拒绝且不会破坏现有数据库；
- [ ] 设置页可查看固定费用与口径、目录实际来源和年度日历状态，并可执行备份、恢复、日志导出；恢复成功后所有页面查询失效并重新读取；
- [ ] 当前年度交易日历必须为 `official` 才能发布构建；旧安装跨年缺日历时仍可启动、备份和浏览历史，仅相关联网能力被阻断；
- [ ] 日志导出不含密钥、Cookie 或用户敏感信息；
- [ ] 应用不存在任何下单入口或券商交易权限。
