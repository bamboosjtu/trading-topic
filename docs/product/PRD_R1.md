# 攒股收息 PRD R1

> 状态：评审收敛版
>
> 更新日期：2026-07-25
>
> 目标形态：单机 Electron 桌面应用
>
> 数据范围：A 股股票
>
> 数据截止日：每次计算均随结果记录，不在文档中写死

## 1. 目标

R1 用一个可运行、可备份、可审计的本地桌面应用验证两件事：

1. 用户能按明确口径回测一只或多只 A 股股票的固定金额攒股方案；
2. 用户能通过手工流水维护真实账户，并得到可复核的资产与收益结果。

R1 的成功标准是“结果算得对、来源说得清、数据拿得走”，不是功能数量。

## 2. 目标用户与核心场景

目标用户是低频交易、愿意手工维护关键流水的 A 股长期投资者。

核心场景：

- 创建固定区间或快捷区间的单标的回测；
- 选择多只股票，以完全相同条件分别回测并排比较；
- 录入真实资金与交易流水；
- 查看当前持仓、现金、总资产、累计盈亏和 XIRR；
- 导出 JSON 备份或日志，在本机恢复并复核。

## 3. R1 范围

### 3.1 历史回测

#### 标的与比较

- 只支持 A 股股票；
- 支持单标的回测；
- 支持多标的同条件并排；
- “并排”表示每只股票使用独立虚拟账户分别运行，不做组合、再平衡或跨标的资金共享。

#### 投入与买入规则

- 每月投入固定金额；
- 用户指定每月买入日；
- 指定日不是交易日时，顺延到该月下一个交易日；
- 区间首月若指定日早于可用数据起点，从首个满足条件的交易日开始；
- 当月指定日之后没有交易日时，该月不买入，结果中必须标记；
- 允许买入零碎股，内部股数保留足够精度，界面默认显示两位小数；
- 每月外部投入在执行日按当日收盘价全额买入，不因一手门槛保留现金；
- 买入价格统一采用实际执行交易日的收盘价；
- 每个并排标的独立结转现金，互不挪用。

#### 分红与公司行动

- 现金分红按登记日持股数量计算；
- R1 按数据源提供的除权除息/到账口径入账，结果中记录采用的事件日期字段；
- 分红现金在事件日加入对应虚拟账户，并按当日收盘价全额回购原标的；
- 送股、转增按登记日持股数量和“每 10 股送转股数”计算，在除权日增加持股；
- 配股等需要额外缴款或用户选择的公司行动仍不自动处理，遇到时必须阻断或标记“尚未验证”。

#### 简化费用

R1 只有一种费用模式，不提供多模型切换：

- 回测买入费用固定为 0；
- 印花税、分红税、过户费和滑点不计；
- 期末资产按市值估算，不假设卖出；
- 费用口径必须显示在结果页和导出文件中。

#### 区间

- 固定区间：用户选择开始日期和结束日期；
- 快捷区间：基于数据截止日提供预设年限；
- 快捷区间的具体选项由界面配置，但最终都转换为明确的开始日期、结束日期和数据截止日；
- R1 不做滚动窗口回测。

#### 输出

每个标的必须输出：

1. 累计投入；
2. 最终资产；
3. 累计盈亏；
4. XIRR；
5. 最大回撤；
6. 累计分红；
7. 期末现金。

口径：

- 最终资产 = 期末持仓市值 + 期末现金；
- 累计盈亏 = 最终资产 - 累计投入；
- XIRR 仅把每次月度外部投入记为负现金流，把期末资产记为正现金流；分红属于账户内部现金流，不重复计入；
- 最大回撤基于“持仓市值 + 现金”的日度总资产序列计算；
- 累计分红按实际入账金额累计，不因后续回购而减少。

并排结果必须同时展示各标的的数据来源、实际计算区间和截止时间，不允许因数据缺口自动改用不同区间而不提示。

回测明细必须区分：

- 本期外部投入与累计外部投入；
- 定投买入成交金额、分红回购成交金额与累计买入金额；
- 现金分红到账、分红回购、送股/转增入账三类事件。

其中“累计买入金额”是从回测开始到当前事件的全部买入成交金额之和，包含
定投买入和分红回购；它不等同于用于计算 XIRR 的累计外部投入。

### 3.2 实际记录

R1 只维护一个人民币本地账户，不做多账户、家庭账户或账户间转移。

#### 流水类型

用户可手工新增以下流水：

- 资金转入；
- 买入；
- 卖出；
- 现金分红；
- 逆回购；
- 资金转出；
- 冲正/修正。

流水采用追加式记录。已参与计算的记录不原地覆盖；冲正创建反向记录，修正由“冲正原记录 + 新增正确记录”组成，并保留关联关系。

#### 最低字段

所有流水共有：

- 唯一编号；
- 业务日期与录入时间；
- 币种（R1 固定为人民币）；
- 备注；
- 创建来源；
- 被冲正记录编号（如适用）。

按类型补充：

- 资金转入/转出：金额；
- 买入/卖出：股票代码、价格、数量、费用；
- 现金分红：股票代码、每股分红或到账总额、登记日、到账日；
- 逆回购：品种、成交日期、本金、成交收益率、期限、费用、到期金额或实际收益；
- 冲正/修正：原因和关联记录。

#### 账户输出

R1 必须输出：

1. 当前持仓；
2. 可用现金；
3. 总资产；
4. 累计盈亏；
5. XIRR。

口径：

- 当前持仓由有效买入、卖出和已确认公司行动推导，不允许另存一份可独立修改的持仓余额；
- 可用现金由资金、交易、分红、逆回购和冲正流水推导；
- 逆回购未到期本金不计入可用现金，但计入总资产；
- 总资产 = 持仓市值 + 可用现金 + 未到期逆回购资产；
- 累计盈亏 = 总资产 + 累计资金转出 - 累计资金转入；
- XIRR 把资金转入视为用户负现金流、资金转出视为正现金流，并以数据截止日总资产作为期末正现金流；
- 持仓估值使用的数据来源和截止时间必须与结果一起展示。

### 3.3 基础能力

- 本地存储：业务数据默认只保存在本机 SQLite；
- 来源追踪：行情、分红和估值结果记录来源、获取时间、数据截止时间和口径版本；
- JSON 备份：导出包含 schema 版本、导出时间、业务数据和必要元数据的 JSON；
- JSON 恢复：导入前完成结构校验和版本检查，先生成当前数据备份，再由用户确认覆盖；
- 日志导出：导出运行日志和错误上下文，不包含 Token、Cookie、账号或个人敏感信息；
- 不执行交易：不接券商、不下单、不请求交易权限，界面明确提示“仅供研究与记录，不构成投资建议”。

## 4. 页面与主流程

R1 只保留四个一级入口，每个页面的设计细节见 [desktop_ui/](desktop_ui/) 目录：

| 页面 | 责任 | 设计简述 |
| --- | --- | --- |
| 回测 | 创建单标的回测、发起同条件并排、查看结果与口径 | [历史回测_ui_brief.md](desktop_ui/历史回测_ui_brief.md) |
| 持仓明细 | 查看持仓、现金、总资产、累计盈亏和 XIRR | [持仓明细_ui_brief.md](desktop_ui/持仓明细_ui_brief.md) |
| 交易流水 | 新增、查看、冲正和修正实际记录 | [交易流水_ui_brief.md](desktop_ui/交易流水_ui_brief.md) |
| 分红日历 | 核对登记日、除权日、到账日和实际分红 | [分红日历_ui_brief.md](desktop_ui/分红日历_ui_brief.md) |
| 设置 | 数据来源、截止时间、费用口径、JSON 备份恢复和日志导出 | [本地设置_ui_brief.md](desktop_ui/本地设置_ui_brief.md) |

首要流程：

1. 用户选择标的与区间并输入月度金额、买入日；
2. 系统校验数据完整性和公司行动支持范围；
3. 核心库计算并返回结果、口径、来源和告警；
4. 用户可导出结果或转到实际流水记录；
5. 真实账户始终从有效流水重算，不从回测结果自动生成交易。

## 5. 非目标

R1 不包含：

- ETF、基金、港股或其他市场；
- 组合回测、再平衡或跨标的资金共享；
- 滚动窗口；
- 精确费用、分红税分档、滑点模拟；
- 剩余现金自动参与逆回购；
- 预计分红、分红日历、估值分位或选股建议；
- 移动端、Web 端、云同步或跨设备自动同步；
- 自动导入券商对账单；
- 券商连接、实盘下单或交易建议。

## 6. 验收标准

### 回测

- [ ] 给定同一输入快照，重复运行结果完全一致；
- [ ] 指定日遇周末、节假日和月末无后续交易日时，行为符合本 PRD；
- [ ] 每笔定投和分红回购都允许零碎股，现金余额不为负；
- [ ] 分红入账、回购、送股/转增和累计分红可逐笔追踪；
- [ ] 七项输出能由交易流水和日度资产序列重算；
- [ ] 多标的并排与分别运行单标的的结果一致；
- [ ] 数据缺失或不支持的公司行动不会被静默忽略；
- [ ] 产品使用位于 `src/desktop/` 内的自有 fixture 完成 golden tests；fixture 可源自已评审研究，但测试运行时不得读取或 import `research/`。

### 实际记录

- [ ] 七类流水均可新增和查看；
- [ ] 冲正/修正不修改原记录，重算后余额正确；
- [ ] 持仓、现金、总资产、累计盈亏和 XIRR 可由流水重建；
- [ ] 逆回购到期前后的可用现金与总资产变化符合定义；
- [ ] 估值结果显示价格来源和截止时间。

### 本地能力

- [ ] 断网时可查看既有数据并执行基于本地快照的计算；
- [ ] JSON 导出后可在空数据库恢复，恢复前后核心汇总一致；
- [ ] 不兼容或损坏的备份被拒绝且不会破坏现有数据库；
- [ ] 日志导出不含密钥、Cookie 或用户敏感信息；
- [ ] 应用不存在任何下单入口或券商交易权限。
