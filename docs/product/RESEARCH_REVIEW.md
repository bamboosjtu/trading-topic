## 三、研究方法学评估（强项）

研究方法学严谨度远超一般个人回测项目，主要体现在以下六点。

### 3.1 数据源治理

腾讯主源 + 新浪备源，东财 `stock_zh_a_hist` 显式禁用、`mootdx.bars` 暂缓；双源相对差异超过 0.2% 即阻断该股全部周期（`labs/bank_dca.py#L385-L414`）。

股票池构建链路：交易所 A 股清单 → 名称/行业初筛 → mootdx F10 主营文本验证 → 2026-07-24 人工核验清单比对（`labs/bank_dca.py#L261-L292`），避免自动筛选遗漏或越界。

### 3.2 复权口径正确

明确用"不复权价 + 显式分红再投资"构建总回报净值，避免前复权价格被误当作可交易价。前复权序列在长期高分红股票上可能接近零甚至为负，不能直接用于跨越多年、包含多笔外部现金流的定投买入。

反向校核：用中证官方全收益指数 `H00300/H00905` 对比价格指数 `000300/000905`，验证"总回报口径 XIRR 必须高于价格口径 XIRR"（`verify_returns.py#L54-L71`）。

### 3.3 风险指标语义分离

| 指标 | 含义 | 计算依据 |
|---|---|---|
| `max_drawdown` | 标的总回报净值最大回撤 | 含分红的标的净值从高点跌了多少 |
| `max_loss_vs_contribution` | 账户相对本金最大浮亏 | 定投账户资产相对累计投入的历史最低浮亏 |
| `volatility` | 标的总回报日收益率年化波动率 | 252 日年化标准差 |
| `strategy_max_drawdown` | 现金流调整后策略净值回撤 | 先剔除每笔新增本金，再衡量策略单位净值回撤 |

三类口径不混用，且在报告中明确解释"当前模型始终满仓、允许碎股且不保留现金，因此后两列数值相同；这是模型条件下的结果相等，不是把两种定义混用"。

### 3.4 XIRR 实现独立可测

存在两套实现互相验证：

- `bank_dca.xirr`（`labs/bank_dca.py#L697-L732`）：二分法
- `analysis.calc_xirr`（`research/bank-dca/analysis.py#L12-L35`）：牛顿法

`verification.json` 显示 7 家银行的 `nav_identity_max_error` 全部 ≤ 1.2e-14，证明标的总回报净值与现金流调整后策略净值在数学上等价。

### 3.5 滚动窗口分析避免单一起点偏差

固定样本（2020-01 至 2026-07）只能回答"这一段历史怎样"，无法判断结论对起点是否敏感。研究包额外实现 `rolling_backtest`（`analysis.py#L181-L207`），对 3/5/10 年期限的全部滚动窗口分别估值，并明确写"相邻滚动窗口高度重叠，胜率不能当作独立重复试验的概率"。

### 3.6 结论强度匹配证据

`七家银行与基准回测报告.md` §七明确列出 5 条限制：

1. 允许碎股，未计股票佣金、最低佣金、印花税、分红税及买卖价差；
2. 分红按除权日收盘立即再投资，真实到账日和成交价可能不同；
3. 204001 使用定盘利率代理个人实际成交收益；
4. 七家银行是事后选择的存续公司，仍有幸存者偏差和选股偏差；
5. 未纳入净息差、不良贷款率、拨备覆盖率、资本充足率和估值变化等基本面解释变量。

并写明"可以比较的是这些历史窗口中银行股相对三个基础基准的结果；不能据此承诺未来收益或把高股息等同于低风险"。

## 五、评审结论

### 5.1 是否可进入产品原型开发

**结论：可以进入产品原型开发，但需明确范围边界与前置条件。**

#### 进入原型的充分条件已满足

1. 回测引擎核心（XIRR、分红再投资、滚动窗口、风险指标）已稳定，单元测试 + 口径校核双通过；
2. 数据源路由策略已验证可行（双源降级、质量门禁）；
3. 金融口径已想清楚（不复权 + 显式分红 vs 前复权），这是产品化的最大风险点，研究阶段已消除；
4. 已有可参考的真实数字（不是凭空设计 UI）；
5. 研究包代码与 Lab Notebook 解耦，纯计算层 `analysis.py` 可直接被产品后端 import 复用。

#### 必须前置解决的 3 个 Blocker

1. **数据快照缺失**：`verify_returns.py` / `build_report.py` 当前跑不起来。需先执行 `uv run --project labs python research/bank-dca/data_fetch.py` 恢复快照，确认报告数字与 `verification.json` 留档一致后再启动产品化。
2. **MVP 范围需收窄**：现有研究只覆盖 MVP 主线一约 62%，若坚持 MVP_DESIGN 全量需求，原型周期会失控。
3. **ETF + 组合回测 + 费用模型**为空白，需决定是放进 MVP 还是延后到 R2。

### 5.2 建议的产品化路径

把原型拆成两段，避免一次性补齐所有研究 gap。

#### 原型 R1（基于现有研究直接产品化）

- 主线一：单标的回测（银行股先行，ETF 用同一引擎扩展）
- 主线一：多标的并排比较
- 主线一：固定/快捷/滚动区间
- 主线一核心输出 1-5、7（已实现的指标）
- 主线二：资金转入/买入/卖出/逆回购的手工记录 + 11 项输出

#### 原型 R2（填补研究 gap 后再上）

- 主线一：组合回测（需新增研究）
- 主线一：简化费用 + 精确费用（需新增研究）
- 主线一：剩余现金逆回购计息（需调整 `simulate_*` 语义）
- 主线一：最长亏损时间 + 分红稳定性 + 历史估值（需新增研究）
- 主线一：ETF 行情接入（数据源已具备，仅需适配）

R1 可立即启动，R2 与研究并行推进。

### 5.3 验收标准

进入 R1 开发前需满足：

- [ ] `data_fetch.py` 成功运行，恢复 `research/bank-dca/data/*.csv` 快照
- [ ] `verify_returns.py` 通过，且 `verification.json` 与历史留档数值一致
- [ ] `build_report.py` 通过，且 `七家银行与基准回测报告.md` 关键数字与留档一致
- [ ] 用户确认研究报告结论（本次评审不含金融结论确认）
- [ ] MVP 范围明确收窄为 R1，R2 需求列入 backlog

进入 R1 开发后，产品后端必须满足：

- [ ] `src/core/` 不得直接复制 `analysis.py`，必须 import 复用或在 sidecar 中作为依赖安装

- [ ] 回测 API 参数命名与研究报告一致（`monthly_amount`、`buy_day`、`lot_size`、`dividend_reinvest` 等）

## 六、风险与待验证问题

1. **ETF 行情接口未验证**：研究包未涉及 ETF，虽然 akshare 提供 ETF 接口，但分红处理（ETF 分红频率、单位净值与收盘价差异）需独立验证。
2. **一手买入 vs 碎股**：Lab1 严格按 100 股整数倍买入，研究包允许碎股。产品化若切回一手，最终市值与 XIRR 会与研究包留档数字不一致，需重新生成 baseline。
3. **费用模型影响未知**：当前完全未计费用，银行股定投的佣金 + 印花税 + 分红税对长期 XIRR 的影响幅度尚未量化。建议 R2 阶段先做敏感性分析，再决定简化费用与精确费用的实现优先级。
4. **逆回购计息语义未定**：MVP 要求"剩余现金参考历史国债逆回购收益"，但研究包把逆回购作为独立基准。产品化需决定：账户内剩余现金是否按 204001 定盘利率逐日计息？还是按用户实际成交收益率？
5. **历史估值数据源未定**：PE/PB/股息率分位数需要额外的基本面数据源，akshare 可提供但需验证质量。
